## Теория

Настройка генерации влияет на распределение возможных следующих токенов. **Temperature** меняет степень случайности выбора: низкие значения делают выбор более предсказуемым, высокие — более разнообразным. Параметр **максимума выходных токенов** ограничивает длину генерации, но слишком малый предел может оборвать правильный ответ.

**Контекстное окно** ограничивает число токенов, которое модель может учитывать за раз. Оно включает инструкции, историю и вопрос; в RAG — также найденные фрагменты. Большее окно позволяет передать больше материала, но увеличивает память и вычисления. Реально доступный предел зависит от модели, формата весов и загрузки в runtime.

**Prompt-шаблон** задаёт задачу и форму ответа. Для сравнения важно менять по одному фактору или явно описывать набор одновременных изменений. Если сразу изменить модель, инструкцию и три параметра, улучшение нельзя приписать одной настройке.

**Квантование** уменьшает точность представления весов модели, например до 4 бит. Это обычно снижает размер модели и потребность в памяти, но может влиять на качество и скорость. Названия `Q4`, `Q8`, `4bit` помогают различать варианты, но фактический расход зависит и от контекста, GPU offload и runtime.

Скорость измеряют одинаковой задачей, записывая время ответа и, если система сообщает, скорость токенов. Память модели зависит от runtime и выделения памяти процессора или видеокарты. Качество лучше оценивать по заранее выбранным критериям вручную или независимой проверкой. Одного ответа недостаточно для устойчивого вывода: повторите сравнение несколько раз при одинаковых условиях.

## Решение

**Замысел.** Лаборатория показывает базовый и настроенный запуск рядом на одном учебном вопросе. Сначала пользователь получает обычный ответ, затем меняет температуру, ограничение ответа, размер контекста, инструкцию или вариант модели и запускает настроенный ответ. Он отмечает три критерия качества и сохраняет результаты вместе с параметрами.

**Устройство.** LM Studio API принимает температуру, максимальный выход, контекст и системную инструкцию на запросе; приложение использует `POST /api/v1/chat` ([официальная схема](https://lmstudio.ai/docs/developer/rest/chat)). В обеих колонках один вопрос. По умолчанию базовый шаблон нейтральный; настроенный просит объяснить понятие начинающему и дать пример. Модель можно выбрать среди загруженных; для теста квантования загрузите в LM Studio подходящий альтернативный файл и обновите список.

Для запуска нужны Node.js 22.13+, LM Studio, загруженная модель и запущенный Local Server. Выполните `npm start` в папке задания и откройте `http://127.0.0.1:3029`. Получите оба ответа по отдельности. Для честного сравнения сохраняйте модель и вопрос одинаковыми, если изучаете только промпт или параметры. При сравнении квантования записывайте точные идентификаторы вариантов.

Впишите память процесса из диспетчера задач или окна LM Studio вручную: API чата не измеряет полное потребление компьютера. Нажмите критерии только после чтения ответа. Повторите серии для оценки стабильности. Протокол скачивается в JSON и не является независимым аудитом качества.

## Результаты и выводы

Интерфейс готов собирать фактические ответы, задержку, токены/с, настройки и ручные отметки качества. В среде разработки модельный API недоступен, поэтому измеренные результаты не выдумывались. Без выбранной модели, аппаратного наблюдения и повторных запусков нельзя утверждать, что оптимизация ускорила ответ или снизила расход памяти.

## Практическая польза

Такой эксперимент помогает выбрать настройки для конкретного помощника: например, краткого справочного чата или объяснения учебных тем. Он показывает, какой набор параметров отвечает требованиям, а какие ограничения остаются незамеченными при сравнении только одного ответа.
