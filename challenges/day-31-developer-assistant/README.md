# День 31. Ассистент разработчика

## Исходное задание

День 31. Ассистент разработчика

Используйте RAG для подключения к документации вашего проекта:

👉 README
👉 project/docs
👉 схемы данных или API-описания

Через MCP подключите ассистента к проекту:

👉 минимум — получение текущей git-ветки
👉 по желанию — список файлов или diff

Реализуйте команду:

👉 /help — ассистент отвечает на вопросы о проекте
👉 использует документацию и контекст проекта

Минимальный результат:

👉 README + папка docs в RAG
👉 MCP — хотя бы git branch
👉 /help отвечает на вопросы о структуре проекта

Результат:

Ассистент разработчика, понимающий проект

## Теория

**Языковая модель** продолжает текст на основе обучения и переданного запроса.
Она не получает автоматического доступа к файлам компьютера и не знает,
какие изменения появились в конкретном проекте. Убедительный ответ о чужой
структуре каталогов поэтому может оказаться выдумкой.

**RAG** (Retrieval-Augmented Generation, генерация с поиском) разделяет ответ
на два этапа. Сначала программа находит материалы, относящиеся к вопросу,
затем модель формулирует ответ с использованием найденных фрагментов.
Например, вопрос «как запустить тесты?» должен привести к разделу запуска,
а не к случайному описанию архитектуры. Поиск и генерация могут ошибаться
независимо: правильная модель не восстановит сведения, которых нет в контексте.

**Индекс** — подготовленное представление документов. Длинный текст делят на
фрагменты, сохраняя путь, заголовок и положение в исходнике. Слишком короткий
фрагмент теряет смысл, слишком длинный занимает контекст и смешивает темы.
Разбиение по заголовкам помогает сохранить границы разделов, но размер
фрагмента всё равно необходимо ограничивать.

**Эмбеддинг** — числовой вектор текста. Для вопроса и документов используют
одну embedding-модель с одинаковой размерностью. Косинусное сходство сравнивает
направления векторов: близкие по смыслу тексты обычно получают более высокий
балл. Это относительный порядок кандидатов, а не вероятность правильности
ответа. Векторы разных моделей нельзя произвольно смешивать.
[OpenAI: embeddings](https://developers.openai.com/api/docs/guides/embeddings).

**Свежий контекст** отличается от справочного. Инструкция в README может
описывать обычную ветку разработки, но фактическая ветка определяется Git
в момент запроса. Для таких данных нужны инструменты. **MCP** (Model Context
Protocol) задаёт обмен между приложением-клиентом и сервером инструментов:
клиент узнаёт каталог возможностей и вызывает нужную операцию с параметрами.
При локальном транспорте stdio сообщения проходят через стандартные потоки
отдельного процесса. Сам протокол не является языковой моделью и не заменяет
поиск по документам.
[Спецификация транспорта MCP](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports).

```text
Вопрос → поиск по документации → подходящие фрагменты ┐
        MCP → свежие сведения о проекте              ├→ модель → ответ + ссылки
                                                    ┘
```

**Проверяемость ответа** требует сохранения источников. Метка рядом с фразой
помогает открыть исходный фрагмент, но сама по себе не доказывает, что вывод
следует из него. Проверяют отдельно качество поиска, соответствие утверждений
источникам и умение отказаться от ответа. Тексты документов также следует
считать данными: инструкция внутри прочитанного файла не должна менять
правила работы помощника.

## Решение

Замысел — дать человеку локальную страницу, на которой можно спросить о
реальном AI Tutors и увидеть основания ответа. Человек обновляет базу знаний,
вводит `/help` и вопрос, затем сопоставляет ответ с найденными разделами и
результатами MCP. Проверка включает вопросы о структуре, запуске и ограничениях,
а также вопрос, на который публичная документация не должна давать ответа.

Приложение самостоятельно запускается на Node.js 22.13+ и не импортирует код
других заданий. Индекс включает корневой README, Markdown в `docs/` и README
заданий. Тексты делятся по заголовкам с ограничением размера; для поиска
используются 512-мерные `text-embedding-3-small` и косинусное сходство.
Генерация выполняется `gpt-5.6-luna` через Responses API. MCP-сервер предоставляет
`git_branch`, `list_files`, `read_file`; при `/help` приложение вызывает первые
две операции. Выбор этих операций задан приложением, а не моделью.

Из папки задания:

```powershell
npm.cmd ci
npm.cmd start
```

Первая команда устанавливает зафиксированные зависимости, вторая открывает
сервер на [127.0.0.1:3031](http://127.0.0.1:3031). Нажмите «Обновить базу»,
затем выполните предложенный `/help`-вопрос. `OPENAI_API_KEY` должен быть
доступен серверу через окружение. Для остановки нажмите Ctrl+C.

Тексты индексируемых документов, вопросы и выбранные фрагменты отправляются
в OpenAI. Секреты, результаты экспериментов и служебные каталоги исключены
из разрешённого корпуса; символические ссылки дополнительно проверяются.
Общий журнал расходов всех пяти дней расположен в
`~/.ai-tutors/days-31-35`; `AI_TUTORS_DATA_DIR` меняет каталог. Лимит $1 действует
на журнал, а не на весь аккаунт. Для продолжения проверенной серии из корня
репозитория задайте `$env:AI_TUTORS_DATA_DIR = Join-Path (Get-Location) '.local-days-31-35'`.
Новый каталог создаёт новый журнал. Тариф оценки консервативный, с учётом
максимальной цены записи кеша; это не сверка счёта провайдера.
[Тариф модели](https://developers.openai.com/api/docs/models/gpt-5.6-luna).

Кнопка «Открыть сохранённый пример» читает публичный протокол без API-вызовов.
Команда `npm.cmd run check` проверяет синтаксис и выполняет локальные тесты;
`npm.cmd run experiment` повторяет платную контрольную серию в пределах журнала.

## Результаты и выводы

Протокол контрольной серии от 2026-10-18 сохранён в
[`results/experiment.json`](results/experiment.json): точные вопросы, ответы,
источники, ветка, usage и время. Локальные тесты проверяют общий бюджет,
диапазоны строк, допустимость ссылок, ограничения путей, настоящий MCP-процесс
и HTTP-границу. Прошли все 5 тестов и проверка синтаксиса. В браузере проверены
страница и открытие сохранённого ответа с шестью источниками и двумя MCP-вызовами.

Индекс включил 87 документов, 388 фрагментов. Выполнены четыре настоящих
`/help`-вопроса: структура, запуск дней 26–30, API-ключи и пароль production-базы.
Точные входы и полные ответы — `runs[0]`–`runs[3]` в протоколе.
Вместе с индексированием серия потребовала 33 API-вызова, расчётно $0,0110536;
неизвестных расходов и оставшихся резервов нет. Эти числа относятся к снимку
корпуса во время проверки, а не ко всем будущим обновлениям.

Результат не означает понимания всего исходного кода. Поиск ограничен корпусом,
цитаты проверяются по существованию меток; смысловое соответствие оценивает
читатель. После изменения документов индекс нужно обновить вручную. Текущая
ветка читается заново при каждом вопросе.

## Практическая польза

Такой помощник сокращает время знакомства с репозиторием: находит инструкции
запуска, объясняет расположение заданий и напоминает проектные ограничения.
Отдельное отображение документации и текущего Git-состояния помогает проверять
советы перед выполнением команд.
