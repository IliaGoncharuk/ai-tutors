# День 10 — управление контекстом без summary

## Исходное задание

День 10. Управление контекстом: разные стратегии (без summary)

Реализуйте в агенте 3 разных стратегии управления контекстом (минимум), и переключатель между ними:

👉 Стратегия 1: Sliding Window

- храните только последние N сообщений
- всё остальное отбрасывайте

👉 Стратегия 2: Sticky Facts / Key-Value Memory

- введите отдельный блок “facts” (ключ-значение), который хранит важные данные из диалога

  (например: цель, ограничения, предпочтения, решения, договорённости)

- обновляйте facts после каждого сообщения пользователя
- в запрос отправляйте: facts + последние N сообщений

👉 Стратегия 3: Branching (ветки диалога)

- сохраните checkpoint в диалоге
- создайте 2 ветки от одного места
- продолжите диалог в каждой ветке независимо
- переключайтесь между ветками

Протестируйте на одном и том же сценарии (например: “собираем ТЗ 10–15 сообщений”):

👉 прогоните сценарий на каждой стратегии
👉 сравните ответы и поведение агента

Сравните:

👉 качество ответа
👉 стабильность (не теряет ли важные детали)
👉 расход токенов
👉 удобство для пользователя

Результат:

Агент с 3 стратегиями управления контекстом (Sliding Window / Facts / Branching) + сравнение результатов

## Теория

Модель видит контекст текущего запроса. Его формируем вручную через
[Responses API](https://developers.openai.com/api/docs/guides/conversation-state).
Window удаляет старые сообщения; Facts оставляет отдельные значения вроде
`budget: "90000"`; Branching хранит выбранный путь `общий диалог → web / bot`.
Ветки изолируют альтернативы, но их история продолжает расти.
Facts — словарь атомарных данных, свободного пересказа и summary здесь нет.

## Решение

**Полная проверка одной командой из корня репозитория:**

```powershell
npm.cmd --prefix challenges/day-10-context-strategies run check:live
```

По очереди выполняются проверка синтаксиса, 14 локальных тестов, затем
реальный API-прогон Window → Facts → Branching (web и bot). При ошибке
локальной проверки запуск останавливается до API. В конце терминал показывает
таблицу, точность итогового ТЗ, общий расход, проверку независимости веток
и автоматический вывод по текущим результатам. Полные данные сохраняются
в новый каталог `results/live-TIMESTAMP`, пути выводятся в терминал.
Нужен `OPENAI_API_KEY` в окружении; каждый запуск выполняет до 63 генераций
с общим лимитом 100000 токенов. При первом запуске после клонирования
установите зависимости: `npm.cmd --prefix challenges/day-10-context-strategies ci`.

Node.js CLI: `/strategy window|facts|branching`, `/facts`, `/history`, `/stats`.
У каждого режима своя память. N=6 отдельных сообщений — три пары user/assistant;
следующий запрос получает этот хвост и новый вопрос. Facts обновляет модель
перед каждым ответом: прежний словарь + хвост + сообщение → JSON-изменения
ключей. Новое значение заменяет старое, `null` удаляет факт. Формат проверяется
через [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)
и локальную валидацию; смысл извлечённых данных всё равно может быть ошибочным.

Память — `~/.ai-tutors/day-10/context.json`; другой абсолютный путь задаёт
`STRATEGIES_AGENT_FILE`. `/reset` очищает все режимы и ветки, сохраняя расход
процесса. Ошибка хода откатывает память, но не потраченные токены.

Ручной диалог из каталога задания: `npm start` или
`npm start -- --strategy=facts`. Отдельные проверки: `npm test`,
симуляция — `npm run demo`, только реальная серия — `npm run demo:live`.

Для ветвления в CLI: `/strategy branching` → диалог → `/checkpoint base` →
`/branch web base` → `/branch bot base` → `/switch web` → диалог →
`/switch bot` → другой диалог → `/switch web`. Команда `/branches` показывает
ветки и checkpoints; создание ветки само её не выбирает.

## Результаты и выводы

Сценарий: **ТЗ сервиса «Репетитор рядом» для взрослых в Перми**. Учебные данные:
бюджет 120000 → 90000 рублей, резерв 15000, срок 2026-11-01, занятия 45 минут,
8 репетиторов, запрет онлайн-оплаты и сбора телефонов, email → Telegram,
напоминание за 24 часа, отмена за 12 часов. После 12-го сообщения — сайт либо
бот; для бота бюджет 60000 и резерв 10000. Точные 15 сообщений и альтернативные
три, ответы и методика находятся в [протоколе](results/2026-09-13-live/report.md),
полные входы API и изменения facts — в [JSON](results/2026-09-13-live/results.json).

Реальный прогон 2026-09-13, GPT-5.6 Luna; одинаковые 15 сообщений, N=6:

| Режим | Проверки: дословно / по смыслу | Токены, включая память | Медиана хода |
| --- | ---: | ---: | ---: |
| Window | 10/39 / 11/39 | 7065 | 1,875 с |
| Facts | 35/39 / 39/39 | 21503 | 3,491 с |
| Branching, путь web | 39/39 / 39/39 | 13637 | 1,562 с |

Проверки на ходах 6/11/15 сравнивают 11+13+15 полей JSON. Разбор по смыслу
засчитывает регистр «Взрослые» и развёрнутое описание сайта; исходные строгие
оценки сохранены. Window потерял ранние условия, итоговое ТЗ содержит только
6 из 15 проверяемых значений. Facts сохранил требования, но извлечение потратило
11983 токена: всего на **57,7% дороже** основной ветки. Ветки сохранили
требования независимо; продолжение bot добавило 4715 токенов и дало 15/15.

Всего 63 генерации, **46920 токенов**, оценка стоимости генераций $0,01090515.
Один прогон не доказывает устойчивого преимущества по скорости. Качество
критериев приёмки и удобство команд разобраны с примерами в
[анализе](results/2026-09-13-live/analysis.md); это не пользовательское исследование.
Прошли 14 локальных тестов: HTTP-перехват SDK, перезапуск двумя процессами
и воспроизведение всех фактических входов и оценок сохранённого прогона без API.

## Практическая польза

Window подходит для коротких локальных уточнений; Facts — для длительного сбора
требований; ветки — для независимого обсуждения вариантов. Команды и ограничения
описаны в [спецификации](../../docs/features/day-10-context-strategies.md).
