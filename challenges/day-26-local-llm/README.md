## Теория

Языковая модель (LLM) вычисляет продолжение текста по входной последовательности. Её параметры задают закономерности, усвоенные при обучении; для ответа модель последовательно выбирает новые токены — части слов или целые короткие слова. Вычисление выполняется на процессоре, видеокарте или их сочетании. Чем больше модель и контекст, тем больше памяти и времени обычно требуется.

**Локальный запуск** означает, что веса модели и вычисления находятся на вашем устройстве или в вашей домашней сети. Это может снизить задержку и дать контроль над данными, но не гарантирует полную приватность: приложение может отправлять телеметрию, а сама модель может иметь лицензионные ограничения. Локальность также не означает, что любая модель поместится в доступную память.

**Квантизация** хранит параметры модели с меньшей точностью, например в 4 или 8 битах вместо 16. Это уменьшает объём памяти и часто ускоряет вычисление, но может ухудшить ответы. Два файла одной модели могут отличаться форматом, квантизацией и совместимостью с оборудованием.

Приложение обращается к модели через **интерфейс программирования приложений (API)**: отправляет модель, сообщения и настройки, затем получает текст ответа и иногда статистику токенов. HTTP API позволяет тестировать модель как отдельную службу; командная строка (CLI) удобна для коротких проверок. Схема: `вопрос → локальный сервер модели → ответ`.

Сложность запроса не является универсальной числовой мерой. Для учебной проверки полезно заранее выбрать разные типы работы: извлечение простого определения, сравнение нескольких факторов и составление плана с ограничениями. Одинаковый набор запросов позволяет повторить проверку на другой модели.

## Решение

**Замысел.** Небольшой локальный сайт показывает, доступен ли сервер модели, и помогает отправить три заранее подготовленных запроса возрастающей сложности. Человек выбирает установленную модель, получает ответы и может скачать протокол с текстами, именем модели и временем ответа. Проверка считается пройденной, когда сервер виден и в протоколе есть три ответа.

**Устройство.** Используется Qwen3 4B Instruct 2507 в формате GGUF и 4-битной квантизации Q4_K_M; модель занимает 2,50 ГБ. LM Studio предоставляет локальный OpenAI-совместимый endpoint `/v1/chat/completions`; Node.js сервер сайта обращается к нему и не отправляет запросы в облачную модель. Документация LM Studio описывает запуск API-сервера и список моделей ([модель](https://lmstudio.ai/models/qwen/qwen3-4b-2507), [сервер](https://lmstudio.ai/docs/developer/core/server), [совместимые endpoints](https://lmstudio.ai/docs/developer/openai-compat)).

Сначала загрузите выбранную модель, поместите её в память и запустите Local Server в LM Studio. Для командной строки (если модель ещё не загружена) выполните:

```powershell
lms get qwen/qwen3-4b-2507                       # загрузить файл модели, около 2,5 ГБ
lms load qwen/qwen3-4b-2507 --context-length 8192 # загрузить модель в память
lms server start --port 1234                     # запустить HTTP API
```

Затем из папки задания выполните `npm start`; сайт откроется на `http://127.0.0.1:3026`. Кнопка «Проверить ещё раз» читает загруженные чат-модели. Кнопки уровней подставляют примеры запросов; кнопка отправки передаёт запрос через сервер сайта. «Скачать протокол» сохраняет ответы текущей сессии в JSON. Команда `npm run experiment` последовательно выполняет три учебных вопроса и сохраняет протокол в `results/experiment.json`.

Нужен Node.js 22.13+. Если порт модели или адрес отличается от стандартного, задайте `LM_STUDIO_URL` при запуске сервера. Для LM Studio с включённой авторизацией передайте токен через `LM_STUDIO_TOKEN`; он остаётся только в окружении Node.js.

## Результаты и выводы

На Qwen3 4B Instruct 2507 выполнены три раздельных запроса через локальный сайт: простой, средний и сложный. Задержки модели составили **448 мс**, **1558 мс** и **2583 мс**. Все три вернули текст; точные формулировки и ответы сохранены в [протоколе](results/experiment.json). Это один последовательный прогретый запуск на компьютере с 31,8 ГБ RAM и 20 логическими процессорами, а не устойчивый бенчмарк. Запуски повторяются командой `npm run experiment`, когда сервер сайта и модель активны.

## Практическая польза

Локальный endpoint позволяет проверить модель до интеграции в программу. Три разных запроса быстрее выявляют, справляется ли она не только с коротким фактом, но и с сопоставлением условий и планированием.
