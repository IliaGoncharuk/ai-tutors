# День 24 — цитаты, источники и анти-галлюцинации

## Исходное задание

🔥 День 24. Цитаты, источники и анти-галлюцинации

Доработайте RAG так, чтобы модель обязательно возвращала:

👉 ответ
👉 список источников (source + section/chunk_id)
👉 цитаты (фрагменты из найденных чанков)

Проверьте на 10 вопросах:

👉 есть ли источники в каждом ответе
👉 есть ли цитаты в каждом ответе
👉 совпадает ли смысл ответа с цитатами

Усиление:

👉 добавьте правило: если релевантность ниже порога — ассистент обязан сказать “не знаю” и попросить уточнение

Результат:

Ответы с обязательными источниками и цитатами + режим “не знаю” при слабом контексте

## Теория

**Ответ с опорой на источники** позволяет проверить происхождение утверждений.
Нужно различать три вещи: документ существует; цитата действительно взята из
него; цитата подтверждает смысл ответа. Например, предложение «читальный зал
открыт по будням» не доказывает, что библиотека работает в воскресенье, даже
если источник и буквальная цитата указаны правильно.

**Цитирование на уровне утверждений** связывает отдельную мысль с конкретным
доказательством. Общий список из десяти документов в конце длинного ответа
не показывает, какой из них подтверждает спорный факт. Полезный адрес содержит
документ, раздел и идентификатор фрагмента. Небольшая точная цитата позволяет
проверить вывод, не перечитывая весь документ.

**Структурированный вывод** задаёт формат: например, список утверждений, у
каждого текст и ссылки на доказательства. Проверка JSON-схемы обеспечивает
форму, но не истинность содержимого. Поэтому приложение дополнительно сверяет
идентификаторы с реально найденным контекстом и ищет цитаты в его тексте.
[Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs).

```text
Найденные фрагменты → утверждения + цитаты → проверка адресов и текста → ответ
                                      ↘ недостаточно доказательств → уточнение
```

**Отказ от ответа** — нормальный результат поиска. Низкое сходство может
означать, что вопрос относится к другой теме. Высокое сходство ещё не гарантирует
ответ: документ о библиотеке может ничего не говорить о потерянном билете.
Поэтому применяют два уровня: порог до генерации и оценку достаточности
информации при формировании ответа. Уточняющий вопрос помогает сузить тему или
получить недостающий документ. Повышение порога обычно увеличивает число отказов.

**Анти-галлюцинации** — набор ограничений и проверок, а не обещание абсолютной
безошибочности. Буквальное совпадение цитаты проверяется программой надёжнее,
чем логическое следование произвольного вывода из неё. Модель может смешать
два компонента, время действия правила или исключение. Для оценки нужны
вопросы с ответами, вопросы без ответов и отдельный разбор смысловой поддержки.
Отказы следует учитывать отдельно от полноценных ответов, иначе система,
которая всегда молчит, получит искусственно хорошую оценку «без ошибок».

## Решение

**Замысел.** Создать локальный помощник, у которого под каждой мыслью можно
раскрыть подтверждающую цитату и адрес документа. Если найденный материал не
позволяет ответить, сайт покажет «не знаю» и уточняющий вопрос. Проверка включает
десять вопросов по базе, посторонние вопросы и отсутствие конкретного факта
в тематически близком документе.

**База и поиск.** В [корпусе](data/corpus.json) — снимок 20 README, 18 628 слов.
Локальная SQLite импортирует готовый [индекс](data/index.json.gz). Эмбеддинги —
`text-embedding-3-small`, 512 измерений. Из 20 кандидатов фильтр оставляет до 5:
порог 0,30, проверка номера дня, исключение почти пустых фрагментов и дублей,
затем эвристическое ранжирование по сходству и словам. Переписывание по умолчанию
выключено: в предыдущем сравнении оно не дало прибавки к фильтру, но требовало
дополнительного запроса. Этот сайт запускается независимо от предыдущего.

**Ответ.** [grounding.mjs](server/grounding.mjs) запрашивает у `gpt-5.6-luna`
JSON: статус, утверждения с цитатами и уточнение. Сервер подставляет source и
section из собственных метаданных: модель выбирает только chunk_id и цитату.
Каждое утверждение должно иметь доказательство. Пробельные различия допускаются
при поиске цитаты, но в ответ подставляется точный фрагмент исходного текста.
Неизвестная ссылка, выдуманная цитата или утверждение без цитаты отклоняют
весь ответ. Вместо него показывается честный отказ с причиной в протоколе.

Если фильтр не оставил фрагментов, генерация вообще не вызывается. Если модель
сама вернула `unknown`, её неподтверждённые утверждения не отображаются.
В отказе список источников явно пуст: приложение не придумывает доказательства
ради формального присутствия ссылки. При принятом ответе раскрываются цитаты,
адреса, поисковый маршрут и точный запрос. Код проверяет происхождение, а
не произвольное смысловое следование; это ограничение написано в интерфейсе.

Нужен Node.js 22.13+. Из папки задания:

```powershell
npm.cmd ci              # установить зависимости
npm.cmd start           # http://127.0.0.1:3024
npm.cmd run check       # локальные проверки, типы, сборка
npm.cmd run experiment  # реальные ответы и проверки отказов через API
```

Для новых запросов нужен серверный `OPENAI_API_KEY`, для сохранённых результатов
ключ не требуется. Остановка — Ctrl+C. Данные — `~/.ai-tutors/rag-campaign`
или `RAG_DATA_DIR`: база дня `day-24.sqlite`, общий кеш и бюджет в
`campaign.sqlite`. Общий лимит серии $1, автоматических повторов API нет.
В OpenAI отправляются вопросы и отобранные фрагменты, индекс остаётся локальным.

## Результаты и выводы

Все вопросы, ответы, цитаты, запросы и причины отказов сохраняются в
[протоколе эксперимента](results/experiment.json). Итоги проверки приводятся
ниже.

Итоговая серия 2026-10-05: 9 из 10 контрольных вопросов получили ответы.
Все 9 принятых ответов содержат проверенные источники и цитаты; смысл всех
их утверждений подтверждён цитатами при разборе агентом. Это не независимая
человеческая экспертиза и не гарантия исчерпывающей полноты. Вопрос об именах
MCP-серверов получил честный отказ: нужная таблица не попала в контекст.

Три дополнительные проверки тоже дали отказ: луковый суп, масса спутника
и не указанный в документах пароль. В первых двух генерация не вызывалась;
для тематически близкого вопроса модель сама признала отсутствие факта.
Таким образом, есть 4 отказа из 13 запросов, а не 13 ответов с цитатами.

Первый [диагностический прогон](results/diagnostic.json) выявил две цитаты со
склейкой через многоточие; сервер их отклонил. Инструкция уточнена: только
непрерывные подстроки, несколько доказательств — несколько отдельных цитат.
В повторном полном прогоне такие ошибки не встретились. Оба прогона сохранены.

Итоговый прогон: 11 генераций, 26 192 входных и 1762 выходных токена,
$0,00866240. Вместе с диагностикой: 24 API-вызова, 51 869 входных и 3574
выходных токена, $0,01724547. Эмбеддинги повторных вопросов взяты из кеша.
Прошли 15 локальных тестов, TypeScript и сборка.

Минимальные проверки и браузерные действия: [протокол проверки](results/verification.md).

## Практическая польза

Проверяемые цитаты полезны для помощников по регламентам, документации и
обучающим материалам. Человек может быстро отличить подтверждённый факт от
предположения, а разработчик — диагностировать плохой поиск, выдуманную ссылку
или неверное толкование настоящей цитаты. Честный отказ показывает, что нужно
добавить в базу знаний.
