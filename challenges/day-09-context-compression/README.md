# День 9 — сжатие истории

## Исходное задание

Хранить последние N сообщений «как есть», заменять остальное summary
(например, каждые 10 сообщений), хранить summary отдельно и подставлять его
в запрос вместо полной истории. Сравнить качество ответов без сжатия и со
сжатием, расход токенов до/после. Результат — агент с компрессией истории,
который экономит токены.

## Теория

Контекст — информация, доступная модели в текущем запросе. Повторная отправка
растущей переписки увеличивает вход. Summary — краткая память о фактах,
ограничениях и решениях; свежие сообщения сохраняют детали последних шагов.
При N=6: `10 старых сообщений → summary первых 4 + последние 6 → новый вопрос`.
Следующее сжатие обновляет прежнее summary вместе с очередной старой частью.
Такой вход формируем сами через [Responses API](https://developers.openai.com/api/docs/guides/conversation-state).

Сжатие может потерять точное число или исправление. Оно само расходует токены:
`экономия = расход полной истории − (ответы со сжатием + создание summary)`.
Фактический расход берём из [usage](https://developers.openai.com/api/reference/typescript/resources/responses/methods/create),
а не из длины текста. Экономия токенов не равна проценту экономии денег: тарифы
входа, выхода и кеша различаются.

## Решение

Отдельный Node.js CLI; N=6, интервал=10 отдельных сообщений, то есть 5 пар
user/assistant. Перед следующим вопросом старый контекст сжимается моделью;
между сжатиями свежая история накапливается. В запросе остаются инструкции,
summary, свежая часть и вопрос. Новые исправления имеют приоритет над summary.

Память сохраняется в `~/.ai-tutors/day-09/context.json`: `summary` отдельно от
`recentMessages`. При ошибке весь ход и сжатие откатываются, расход сохраняется.
Команды: `/summary`, `/history`, `/stats`, `/reset`, `/exit`.

```powershell
cd challenges/day-09-context-compression
npm ci
npm run demo                          # симуляция без API
npm start                            # API: нужен OPENAI_API_KEY в окружении
npm start -- --keep=8 --every=12       # параметры — чётные числа
npm start -- --full                   # отдельный файл полной истории
npm run demo:live                     # API-сравнение: до 43 генераций
npm test
```

## Результаты и выводы

Локальная симуляция, 20 ходов в каждом режиме:

| Метрика | Без сжатия | Со сжатием |
| --- | ---: | ---: |
| Проверки фактов, исправлений и расчёта | 32/32 | 32/32 |
| Токены ответов: вход + выход | 84 258 | 42 418 |
| Создание summary: вход + выход | 0 | 5 619 |
| Всего условных токенов | 84 258 | 48 037 |

Чистая экономия — **43,0%**, включая три summary. Повторяющиеся заметки хорошо
сжимаются. Четыре контрольных ответа сохранили факты, новый бюджет, новый
формат и запрет платных сервисов. Эти ответы запрограммированы симулятором:
реальная модель пока не проверена, переносить на неё 43% и 32/32 нельзя.
На коротком диалоге summary может дать перерасход; потерянные детали не восстановятся
из свежей истории. [Поведение и проверки](../../docs/features/day-09-context-compression.md).

## Практическая польза

Подходит для длительных учебных диалогов и помощников по проектам: сохраняет
рабочие условия при меньшем повторном входе. Точные обязательные данные лучше
дополнительно хранить структурированно; summary не заменяет архив переписки.
