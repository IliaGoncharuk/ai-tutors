# День 6 — первый агент

Интерактивный CLI принимает сообщения пользователя, передаёт их отдельному
агенту, вызывает OpenAI Responses API и выводит ответы в терминал. Агент хранит
переписку текущей сессии и при каждом ходе отправляет модели весь диалог.

## Что такое агент

Одиночный API-вызов — это функция вида «получить текст, отправить его модели,
вернуть ответ». Агент — отдельная программная сущность, которая владеет полным
циклом обработки:

1. принимает пользовательский ввод;
2. применяет входную политику;
3. объединяет сообщение с собственной памятью;
4. формирует запрос к LLM;
5. применяет выходную политику;
6. сохраняет успешный ход и возвращает результат интерфейсу.

В этой реализации `cli.mjs` ничего не знает о формате Responses API и не
управляет историей. Вся логика находится в классе `Agent` из `agent.mjs`.

## Политики и память

**Input policy** определяет, какой ввод агент принимает. Базовая политика
удаляет пробелы по краям, отклоняет пустые сообщения, нестроковые значения и
текст длиннее 8000 символов.

**Output policy** определяет, какой ответ считается пригодным. Она принимает
только завершённый непустой текстовый ответ. Если модель вернула пустой или
незавершённый результат, он не попадает в историю.

**Память** — массив сообщений с ролями `user` и `assistant`. Он живёт внутри
экземпляра агента, не записывается на диск и очищается командой `/reset` или при
завершении процесса. Новый ход фиксируется атомарно: сообщение пользователя и
ответ добавляются вместе только после успешного вызова и проверки результата.

При каждом запросе агент передаёт всю накопленную переписку в поле `input`.
Это самый простой способ вручную управлять контекстом, но стоимость и размер
запроса растут с длиной диалога. В реальном долгоживущем продукте понадобятся
лимит истории, суммаризация или compaction.

## Нужен ли judge

Judge — отдельный проверяющий результата. Это может быть детерминированное
правило, тест или ещё один вызов LLM, оценивающий корректность и формат ответа.
Judge полезен, когда агент должен выбирать из нескольких кандидатов или
автоматически проверять качество. Для простого чата Дня 6 он не нужен, поэтому
в код не добавлен: его наличие увеличило бы сложность и могло бы удвоить число
платных вызовов.

## Несколько агентов

`Agent` не использует глобальную изменяемую память. Каждый вызов
`new Agent(config)` создаёт независимую сущность со своими инструкциями,
политиками и перепиской. Поэтому приложение при необходимости может создавать
много агентов с разными конфигурациями. Само создание объектов не вызывает API;
массовый параллельный запуск потребовал бы отдельно контролировать расходы,
ограничения частоты и число одновременных запросов.

## Поток данных

```text
пользователь → CLI → input policy → память → Responses API
                                              ↓
пользователь ← CLI ← output policy ← ответ модели
```

## Структура

- `agent.mjs` — агент, его конфигурация, память и полный цикл запроса;
- `policies.mjs` — базовые входная и выходная политики;
- `cli.mjs` — ввод и вывод в терминале;
- `test/agent.test.mjs` — проверки без реальных API-вызовов;
- `.env.example` — безопасный пример имени переменной окружения.

## Запуск

Требуется Node.js 22.13 или новее и переменная окружения `OPENAI_API_KEY`.

```powershell
cd challenges/day-06-first-agent
npm install
npm start
```

Команды CLI:

- обычный текст — отправить сообщение агенту;
- `/reset` — забыть текущую переписку;
- `/exit` — завершить программу.

Проверить наличие ключа, не выводя его значение:

```powershell
if ($env:OPENAI_API_KEY) { 'OPENAI_API_KEY доступен' } else { 'Ключ не найден' }
```

## API и безопасность

Агент использует `gpt-5.6-luna`, Responses API, `reasoning.effort: none`,
`max_output_tokens: 800` и `store: false`. Параметр `store: false` отключает
хранение ответа для последующего получения через API; локальной памятью
диалога управляет сам агент.

Ключ читается только из `OPENAI_API_KEY` во время запуска. Не добавляйте его в
исходники, README, `.env.example`, логи или Git. Подписка ChatGPT не включает
расходы OpenAI API; каждый успешный запрос может быть платным.

Официальная документация:

- <https://developers.openai.com/api/reference/typescript/resources/beta/subresources/responses/methods/create>

## Проверки

```powershell
npm test
npm run lint
```

Тесты подменяют LLM-клиент и не делают платных запросов. Они проверяют политики,
полный контекст диалога, очистку памяти, атомарность истории, защиту деталей
ошибки провайдера и запрет двух одновременных ходов одного агента.
