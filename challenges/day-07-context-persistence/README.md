# День 7 — сохранение контекста

CLI-агент сохраняет сообщения в JSON после каждого успешного ответа. При новом
запуске он загружает переписку и передаёт её модели вместе со следующим вопросом.
Память переживает завершение процесса; команда `/reset` начинает новый диалог.

## Запуск

Требуется Node.js 22.13+ и `OPENAI_API_KEY` в окружении терминала.

```powershell
cd challenges/day-07-context-persistence
npm ci
npm start
```

При старте CLI показывает путь к JSON и количество восстановленных сообщений.
По умолчанию используется `<домашний каталог>/.ai-tutors/day-07/messages.json`.
Путь не зависит от текущей рабочей директории; файл создаётся при первом
успешном ходе или `/reset`. Не запускайте два приложения с одним файлом истории
одновременно.

Для отдельного диалога задайте другой **абсолютный путь вне репозитория**:

```powershell
$env:AGENT_HISTORY_FILE = Join-Path $env:USERPROFILE '.ai-tutors/day-07/demo.history.json'
npm start
```

При перезапуске используйте тот же путь. В новом терминале нужно повторить
настройку `AGENT_HISTORY_FILE`, если она отличается от пути по умолчанию.
`.env.example` показывает имена переменных; CLI не загружает `.env` автоматически.

| Команда | Действие |
| --- | --- |
| Обычный текст | Отправить сообщение с полной восстановленной историей. |
| `/history` | Показать сохранённый диалог без вызова API. |
| `/reset` | Сохранить пустую историю и очистить память. |
| `/exit` | Завершить приложение; история уже сохранена. |

## Проверка на практике

1. Запустите `npm start` и напишите: «Условное имя проекта — Кедр. Запомни его».
2. Дождитесь ответа, введите `/exit` и снова выполните `npm start`.
3. Убедитесь, что при старте указано `Восстановлено сообщений: 2`.
4. Спросите: «Как называется проект, о котором мы говорили?».
5. Агент должен ответить «Кедр». `/history` покажет оба хода, в JSON будет четыре
   сообщения. После `/reset` и следующего запуска история останется пустой.

Автоматическая воспроизводимая проверка без API:

```powershell
npm run demo
```

Она запускает и завершает **два отдельных процесса CLI**. Первый сообщает
случайное проверочное слово, второй спрашивает его без повторения в новом
сообщении. Поддельный LLM-клиент ищет слово только в переданном ему контексте.
Второй процесс запускается из другой рабочей директории. Проверяются ответ,
неизменность первых двух сообщений и рост JSON с двух до четырёх сообщений.

Тот же сценарий с настоящей моделью:

```powershell
npm run demo:live
```

Это **два платных запроса** к `gpt-5.6-luna`, до 800 выходных токенов каждый,
без автоматических повторов. Используются только вымышленные проверочные
данные. Оба вида демонстрации создают отдельный временный файл вне репозитория,
не затрагивают обычный диалог и удаляют свою временную папку после проверки.

## Устройство

- `agent.mjs` — класс `Agent`: загружает историю при создании, применяет политики,
  формирует запрос, проверяет ответ и фиксирует успешный ход.
- `history-store.mjs` — `JsonHistoryStore` с синхронными `load()` и `save()`:
  чтение, проверка формата и замена файла после записи.
- `cli.mjs` — ввод, вывод и команды; сам не собирает API-запрос и не записывает
  историю. Для проверки без сети можно передать `client` в `runChat()`.
- `scripts/restart-demo.mjs` — проверка полного перезапуска; `offline-cli.mjs` —
  её детерминированный провайдер.
- `test/persistence.test.mjs` — проверки хранения и CLI.

Входная и выходная политики переиспользуются из
[Дня 6](../day-06-first-agent/policies.mjs). Сам День 6 остаётся примером памяти
текущего процесса; для запуска Дня 7 достаточно установить зависимости здесь.

JSON имеет версию формата и массив `messages`:

```json
{
  "version": 1,
  "messages": [
    { "role": "user", "content": "Условное имя проекта — Кедр." },
    { "role": "assistant", "content": "Запомнил: Кедр." }
  ]
}
```

Сохраняются только роли и текст завершённых ходов. Модель, текущие инструкции
и лимиты задаются кодом; ключ, объект SDK и полный ответ провайдера в JSON не
попадают. История не обрезается и не суммируется.

Порядок фиксации: проверить ответ → записать новую историю во временный файл
рядом с основным → сбросить запись на диск (`flush: true`) → заменить основной
файл через `renameSync` → обновить память → показать ответ. Поэтому обычный
выход не требует отдельного сохранения. Синхронная запись подходит для маленького
CLI с одним активным ходом.

## Ошибки и ограничения

- Отсутствующий файл означает новый диалог. Повреждённый JSON, неизвестная
  версия, неверные роли, пустые сообщения и неполные пары останавливают запуск.
  Файл не перезаписывается: восстановите его из копии или выберите другой путь.
- Ошибка API, пустой или незавершённый ответ не меняют историю. При ошибке записи
  ход не фиксируется и ответ не показывается как успешный. API-запрос к этому
  моменту уже мог быть оплачен; повтор сообщения будет новым запросом.
- Неудачный `/reset` оставляет прежнюю память. Успешный сброс сохраняет пустой
  JSON; это очистка текущего диалога, без механизма отмены или резервной копии.
- При принудительной остановке во время API-запроса последний незавершённый
  ход может потеряться. Уже сохранённые ходы доступны после перезапуска.
  При остановке во время записи может остаться временный файл; загрузчик читает
  только основной JSON. Резервное копирование и гарантии при сбое питания
  не реализованы.
- Один файл предназначен для **одного работающего процесса**. Межпроцессной
  блокировки нет; параллельные экземпляры могут перезаписать историю друг друга.
  Для них задавайте разные пути. SQLite с транзакциями разумнее для множества
  сессий или конкурирующих записей.
- Полная история увеличивает размер и стоимость каждого запроса. При превышении
  окна контекста запрос может завершиться ошибкой; автоматического сокращения нет.

## API и данные

Восстановленные сообщения передаются в `input` Responses API с ролями `user` и
`assistant`. Используются `reasoning.effort: none`, `max_output_tokens: 800`,
`store: false`; локальная память не зависит от `previous_response_id`.
Ручную передачу истории описывает
[официальная документация OpenAI](https://developers.openai.com/api/docs/guides/conversation-state).
Запись и замена файла используют
[Node.js File System API](https://nodejs.org/api/fs.html).

JSON содержит открытый текст переписки и не шифруется. Не храните в нём секреты
и не добавляйте личные диалоги в публичный Git. На POSIX новые каталоги и файлы
создаются с режимами `0700` и `0600`; в Windows доступ определяется ACL каталога.
Правила обращения с ключами — в
[ограничениях проекта](../../docs/agent/CONSTRAINTS.md#публичность-и-чувствительные-данные).
