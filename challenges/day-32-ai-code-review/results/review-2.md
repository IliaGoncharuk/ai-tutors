# AI-ревью: Учебный diff: корректное форматирование

Обнаружена одна конкретная проблема: изменение ломает функцию для числовых значений, не являющихся конечными обычными числами. Для ожидаемых денежных чисел форматирование до четырёх знаков выглядит намеренным отображением.

## P2 · `displayCost` падает на строках и специальных числовых значениях

challenges/day-32-ai-code-review/fixtures/display.mjs:2 · bug

Раньше функция выполняла конкатенацию и принимала значения, приводимые к строке: например, `displayCost('1.2')` возвращала `$1.2`. Теперь вызывается `cost.toFixed(4)`: у строк метода нет, поэтому возникает TypeError. Кроме того, для `null`/`undefined` функция также падает, а для `NaN` и `Infinity` результатом будет `$NaN`/`$Infinity`, что может быть неприемлемо для отображения стоимости. Проблема проявится, если значение приходит из JSON, формы или другого слоя как строка, либо если расчёт стоимости невалиден.

Рекомендация: Явно определить контракт входа и нормализовать значение до форматирования: например, принимать только конечное число и возвращать безопасное состояние для остальных значений, либо выполнять `Number(cost)` с проверкой `Number.isFinite`. Если строки не поддерживаются по контракту, добавьте проверку и тесты, чтобы ошибка была диагностируемой, а не возникала внутри `toFixed`.
