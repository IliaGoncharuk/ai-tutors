## Теория

**Интеграция модели** — соединение пользовательского приложения с отдельным процессом, который выполняет генерацию текста. Приложение отвечает за интерфейс и подготовку входных данных; модельный сервер загружает веса, управляет вычислениями и возвращает результат. Такое разделение позволяет заменить модель, не переписывая весь интерфейс.

В чате запрос — это не только последняя фраза, но и последовательность сообщений с ролями пользователя и помощника. Если отправлять лишь последний вопрос, продолжения вроде «почему?» лишаются контекста. Передача истории помогает связать реплики, но расходует контекстное окно — максимальный объём текста, который модель учитывает за один вызов.

Локальный HTTP API обычно доступен только на компьютере, где запущен модельный сервер. Это снижает сетевую поверхность и позволяет браузерному интерфейсу не связываться напрямую с внешним API. Сервер приложения может скрыть детали подключения и проверить размер входного запроса. При этом доступность модели, приложения и их сетевых портов — отдельные условия.

**Состояние интерфейса** хранит текущие сообщения для отображения. **Контекст модели** — та часть переписки, которую приложение фактически отправляет при следующем запросе. Эти наборы могут различаться: например, старые сообщения можно оставить на экране, но обрезать по лимиту контекста.

## Решение

**Замысел.** Локальный чат показывает, как реальное приложение принимает сообщение, передаёт модельный контекст локальной LLM и отображает ответ. Пользователь может задать несколько связанных вопросов и начать новый диалог. Для проверки следует убедиться, что ответы приходят при отключённом интернете и не накапливаются в облачном сервисе.

**Устройство.** Сайт и Node.js сервер запускаются независимо от LM Studio. Браузер отправляет накопленную историю на сервер приложения; сервер обращается к `/v1/chat/completions` LM Studio и возвращает ответ. Модельный токен задаётся только в окружении сервера при необходимости. Совместимость endpoint описана в [официальной документации LM Studio](https://lmstudio.ai/docs/developer/openai-compat).

Нужен Node.js 22.13+ и загруженная модель с запущенным Local Server в LM Studio. Выполните `npm start` из папки задания и откройте `http://127.0.0.1:3027`. Сообщения живут в памяти вкладки; кнопка «Новый диалог» очищает их. Один вызов передаёт не более 40 реплик и 12 000 символов контекста. Для разговора с контекстом задайте последовательность, например: «Составь план прогулки по городу» → «Сделай его на час».

## Результаты и выводы

Проведены два последовательных запроса через приложение к локальной `qwen/qwen3-4b-2507`. На первом задании модель сохранила длительность перерыва, но ошиблась в общей длительности плана. Во втором сообщении контекст переписки был передан, однако модель снова нарушила ограничение и завершила ответ по лимиту длины. Результат подтверждает локальную передачу контекста и отображение ответов, но показывает, что числа и расписания нужно проверять отдельно. Замеры одной короткой серии не являются бенчмарком; точные запросы, задержки и наблюдения — в [протоколе локальной проверки](results/local-chat-check.json).

## Практическая польза

Этот шаблон подходит для внутренних помощников, черновиков и локальной обработки текстов, когда важно контролировать размещение данных и не зависеть от облачного API. Доступность модели зависит от ресурсов компьютера.
