# День 4 — температура

Локальная веб-лаборатория и два реальных эксперимента: в каждом один запрос,
три температуры, по три повтора. Все 18 ответов получены через OpenAI Responses
API 2026-09-05. Модель — `gpt-5.6-luna`.

## Задание

Выполнить одинаковый запрос с `temperature = 0`, `0.7` и `1.2`, сравнить
ответы по точности, креативности и разнообразию. На основе примеров
сформулировать, для каких задач подходит каждая настройка.

Полные условия реализации и критерии приёмки — в
[спецификации задания](../../docs/features/day-04-temperature.md).
Результат этой работы — веб-интерфейс, CLI-скрипт, сохранённые ответы
и два исследования ниже.

## Справка: что меняет temperature

Модель генерирует текст последовательностью токенов — небольших фрагментов
текста. Температура влияет на случайность выбора следующего токена:
низкие значения делают выбор более предсказуемым, высокие расширяют
вариативность. Responses API описывает диапазон от `0` до `2` и рекомендует
менять либо `temperature`, либо `top_p`, а не оба параметра одновременно.
[Источник: OpenAI API Reference](https://developers.openai.com/api/reference/cli/resources/responses/methods/create).

| Настройка | Ожидание до эксперимента |
| --- | --- |
| `0` | Больше повторов и привычных формулировок |
| `0.7` | Больше вариантов формулировок и идей, чем при нуле |
| `1.2` | Более широкий поиск вариантов, требующий оценки их уместности |

Это рабочие ожидания, а не гарантии качества. Температура не добавляет
модели знаний и не проверяет факты. Более необычный ответ может быть
неудачным, а повторяемый — ошибочным. Не стоит считать `0` гарантией
побуквенного совпадения: в сохранённой серии есть контрпример.

Поддержку параметра нужно проверять для конкретной модели и режима.
В этой серии API принял все три температуры и вернул их в метаданных.
Использованный `reasoning.effort: none` входит в доступные режимы
[`gpt-5.6-luna`](https://developers.openai.com/api/docs/models/gpt-5.6-luna).

## Первый эксперимент: команда роботов

Во всех девяти вызовах отправлен один и тот же запрос:

> В мастерской было 12 роботов. Привезли ещё 8, затем 5 отправили в школу.
> Сколько роботов осталось? Покажи вычисление. Придумай три разных названия
> для оставшейся команды и короткий девиз. Не добавляй новых фактов
> о количестве роботов.

Арифметическая часть имеет эталон `12 + 8 − 5 = 15`, а названия и девиз
оставляют пространство для творчества.

| Параметр | Значение |
| --- | --- |
| API | `POST https://api.openai.com/v1/responses` |
| Модель | `gpt-5.6-luna` |
| Общая инструкция | `Отвечай по-русски.` |
| Температуры | `0`, `0.7`, `1.2` |
| Повторы | 3 на каждую температуру, всего 9 вызовов |
| Порядок | Три круга `0 → 0.7 → 1.2` |
| Лимит ответа | `max_output_tokens: 600` |
| Reasoning | `effort: none` |
| Хранение ответа для последующего получения через API | `store: false` |
| `top_p` | Не передаётся |
| История и инструменты | Не передаются; каждый запрос независим |

Полный текст запроса зафиксирован в [скрипте](experiment.mjs), а фактически
отправленные параметры — в [JSON результатов](results/2026-09-05/results.json).
Там же записаны модель и температура из ответа API, время, статус и usage.

Критерии сравнения:

- **Точность:** правильные итог и вычисление; отдельно — три разных названия,
  короткий девиз и отсутствие новых численных фактов.
- **Креативность:** образность и уместность названий и девизов. Это качественная
  оценка с примерами, без автоматических баллов и дополнительных API-вызовов.
- **Разнообразие:** число разных полных ответов, названий и девизов внутри
  каждой температуры. Разные строки не обязательно означают разные идеи.

### Точность и соблюдение условия

Все девять ответов содержат верное вычисление и итог **15**. На этой задаче
разницы в арифметической точности не обнаружено. Все ответы также содержат
три различных названия и один короткий девиз.

В третьем повторе при `0.7` модель предложила **«Железная пятёрка»**.
Это название ассоциируется с пятью участниками, хотя осталось пятнадцать.
Буквально модель не утверждает, что роботов пять, поэтому это не ошибка
вычисления и не однозначное новое численное утверждение. Однако название
неудачно в контексте запрета добавлять численные факты: при строгой оценке
соответствия смыслу задания его стоит отклонить. Два других ответа при `0.7`
и все ответы остальных температур такого замечания не имеют.

### Креативность

При `0` названия описательные: «Робоотряд», «Механические мастера»;
«Стальные искры» добавляют образность. Девиз одинаков во всех повторах.

При `0.7` появляется компактное слово «Робоискра», меняются сочетания
названий. При этом «Железная пятёрка» показывает, что новое название может
хуже соответствовать контексту. Рост числа вариантов сам по себе не означает
роста их качества.

При `1.2` во втором повторе встречаются «Стальные умники», «Искры будущего»
и девиз об открытиях. По качественной оценке этот пример образнее обычного
«Механического отряда». Но остальные ответы остаются близкими по стилю:
«Стальные помощники», «Механический строй», привычный девиз о совместной
работе. Устойчивого превосходства `1.2` по креативности серия не доказывает.

### Разнообразие

При `0` первые два ответа полностью совпали, третий изменил два названия.
При `0.7` и `1.2` все три полных текста различаются. Обе ненулевые настройки
дали одинаковые показатели: восемь разных названий и два девиза.

Разнообразие оказалось выше, чем при нуле, но переход от `0.7` к `1.2`
не увеличил эти показатели. Во всех группах сохранились одинаковая структура
ответа и арифметическая часть. Изменения сосредоточены в творческой части.

## Второй эксперимент: мастерская снов

В задаче с роботами изменялись главным образом короткие названия. Для более

Придумай один необычный способ ремонта сна и опиши его. Добавь заголовок и неожиданную заключительную фразу. Объём — 80–120 слов. Не меняй обязательные факты и не добавляй других условий обслуживания.

Модель, общая инструкция, лимит 600 токенов, температуры и число повторов
остались прежними. Изменилось содержание запроса. Сравнение температур

### Точность: факты соблюдены, лишние условия встречаются

Ручное чтение подтвердило сохранение трёх обязательных фактов во всех ответах.
В каждом есть заголовок, описанный способ ремонта и заключительная фраза.
Все тексты уложились в заданный диапазон длины.

При этом три ответа явно расширили условия обслуживания:

- `0`, повтор 1: «Заберите исправленный сон до рассвета» — придуман срок выдачи.
- `0.7`, повтор 1: «Заберите сон до полуночи или оставьте его нам» — добавлены
  срок и варианты обращения с готовым сном.
- `0.7`, повтор 3: «А если сон не починится, мы отремонтируем вашу реальность» —
  появилась новая условная гарантия услуги.

При `1.2`, повтор 2, фраза «ваша подушка принесёт чек» создаёт ассоциацию
с оплатой. Это неоднозначный художественный образ: он не утверждает цену
или обязанность платить, поэтому отдельно отмечен, но не посчитан явным
изменением условий. Автоматический поиск слова «бесплатный» такую
неоднозначность не обнаруживает.

### Креативность: больше деталей, но общая идея повторяется

Во всех девяти ответах способ ремонта связан с **лунным эхом, звуком или
лунным отражением**. Даже названия «лунная перепрошивка» и «перепрошивка
лунным эхом» остаются вариациями близкого мотива. Во всех вариантах есть
образность, но переход к высокой температуре не дал девять концептуально
разных способов ремонта.

Различия лучше видны на уровне деталей:

- При `0` сон вспоминает свою форму от тихого звука, получает новый ритм
  или восстанавливается звуками, извлечёнными из трещин.
- При `0.7` встречаются встряхивание сна в банке, возвращение запаха,
  звука и цвета в обратном порядке, нота из мыльного пузыря между облаками.
- При `1.2` звук извлекают из тени, добавляют дождь или пришивают к сну
  счастливые случайности.

Финалы варьируются заметно: сон остаётся мастером, просыпается раньше хозяина,
стучит в дверь или ремонтирует саму мастерскую. Восьми ответам достался
одинаковый заголовок о ремонте после заката; только третий ответ при `1.2`
получил более короткий заголовок. Это ещё один пример повторения шаблона
при разных температурах.

### Разнообразие: различать формулировки и идеи

Полные тексты различаются во всех девяти запусках, включая три ответа при
нуле. Но этот показатель достигает максимума уже при `0` и больше не
помогает разделить настройки.

Для дополнительного сравнения в интерфейсе показано **среднее расстояние
Жаккара между наборами слов**: для каждой пары ответов вычисляется
`1 − число общих слов / число слов в объединении`, затем берётся среднее
по трём парам и округляется до целого процента. `0%` означает одинаковые
наборы слов, `100%` — отсутствие общих слов. Регистр и пунктуация не учитываются;
повторы слова внутри ответа не добавляют ему веса. Это лексическая,
а не смысловая метрика.

В серии со снами она составила **67% / 75% / 70%**. Максимум здесь у `0.7`,
а не у `1.2`. Различия деталей стали нагляднее, но вывод «чем выше температура,
тем разнообразнее идеи» эксперимент не подтвердил. Во всех группах
сохранился общий мотив лунного ремонта.

## Локальная веб-лаборатория

Интерфейс показывает три температуры рядом и переключает первый, второй
и третий повторы одновременно во всех колонках. Можно выбрать один из двух
сценариев, посмотреть сохранённую серию, запустить новую или скачать
результат в Markdown и JSON. При открытии показана сохранённая серия
с роботами; переключение на сны также не вызывает API.
Такие ответы помечены «Сохранённый эксперимент», рядом показана дата.
После нажатия кнопки запуска появляется пометка «Текущий запуск».

Новый запуск выполняет девять последовательных вызовов, передавая каждый
полученный ответ в интерфейс. Повторная отправка блокируется во время серии
как кнопкой, так и сервером в рамках его процесса. Сервер принимает запуск
только со страницы того же локального адреса. Ошибка останавливает серию
без автоматических повторов; частичные ответы доступны для экспорта.
При закрытии страницы новые вызовы прекращаются после обнаружения разрыва
соединения; уже отправленный запрос может тарифицироваться.

Галочки в карточке — **проверки текстовых признаков**, а не полная оценка:
название, время, упоминание бесплатного ремонта и длина; для роботов —
выражение расчёта, три нумерованных пункта и упоминание девиза. Противоречия,
уместность финала и дополнительные условия оцениваются чтением ответа.

Слова считаются общей функцией в [assessment.mjs](assessment.mjs):
последовательности букв/цифр, включая соединённые внутренним дефисом или
двоеточием части. Заголовок входит в длину, `19:00` считается одним словом.
Алгоритм одинаков для карточек и таблицы исследования.

Веб-запуски хранятся в памяти страницы до перезагрузки; скачайте нужный результат.
Сервер не записывает их в каталог исследования. CLI сохраняет результаты
на диск по прежней схеме. Обе точки входа используют [core.mjs](core.mjs).

## Как повторить

Требуется Node.js 22.13 или новее. При первой установке веб-интерфейса
установите зависимости и запустите локальный сервер:

```powershell
cd challenges/day-04-temperature
npm --prefix web ci
npm run dev
```

При обычном повторном запуске достаточно `npm run dev` из каталога задания.
Перед повторной установкой `npm --prefix web ci` остановите работающий сервер
через `Ctrl+C` в его терминале. Команда `npm ci` сначала удаляет существующий
`node_modules`; на Windows процессы Vinext/Miniflare могут удерживать его файлы
и вызвать `EBUSY: resource busy or locked`. Если установка уже прервалась,
после остановки сервера повторите `npm --prefix web ci`, затем `npm run dev`.
[Поведение npm ci](https://docs.npmjs.com/cli/v11/commands/npm-ci/).

Откройте [локальную лабораторию](http://localhost:3004/). Для чтения сохранённых
ответов ключ не нужен; для новых запросов сервер должен получить
`OPENAI_API_KEY` при запуске. Приложение работает локально и не публикуется.

Для CLI сторонних зависимостей нет. Следующие команды выполняются из корня
репозитория:

```powershell
cd challenges/day-04-temperature
node experiment.mjs --dry-run
node --test tests/*.test.mjs
```

Эти команды показывают девять запланированных запросов и выполняют локальные
тесты **без API и расходов**. Запуск без аргументов выводит справку.

Для реального эксперимента нужна переменная `OPENAI_API_KEY` в окружении.
Проверить только наличие, не выводя ключ:

```powershell
if ($env:OPENAI_API_KEY) { 'Ключ доступен' } else { 'Ключ не найден' }
```

Следующая команда запускает **новую серию из девяти платных вызовов**:

```powershell
node experiment.mjs --run --scenario dreams --output results/my-next-dreams-run
```

Параметр `--scenario robots` выбирает роботов (это также значение по умолчанию),
`--scenario dreams` — мастерскую снов. Он работает и с `--dry-run`.
Используйте новый каталог для каждой серии. Скрипт откажется перезаписывать
существующий `results.json` до отправки запросов. После каждого ответа
сохраняются JSON и Markdown-протокол. При ошибке серия останавливается,
автоматических повторов и автоматического продолжения нет; уже полученные
ответы остаются на диске. Повторный запуск расходует баланс заново.

Новый протокол не меняет выводы этого README: они относятся к двум сохранённым
сериям от 2026-09-05. Новые ответы нужно оценивать отдельно.
Ключ читается только из окружения и не записывается в результаты;
общие правила — в [CONSTRAINTS](../../docs/agent/CONSTRAINTS.md).

## Проверки и ограничения исследования

Локальные проверки:

```powershell
node --test tests/*.test.mjs
npm run test:runtime
npm run lint
npm run build
```

14 тестов на Node.js проверяют параметры и сохранение запросов, совместимость первого
сценария, новый сценарий в отчёте, ошибки без повторов, отмену, подсчёт слов,
лексическую метрику, локальный серверный маршрут, защиту от параллельного
запуска и сохранение частичных ответов. Все тесты выполняются без OpenAI API.
Отдельный тест `npm run test:runtime` выполняет полный поток девяти ответов
в workerd с локальной подменой API. Он проверяет настоящий конструктор Request
и совместимость параметров с серверным runtime; платных вызовов нет.
Выполнены линтер, сборка, проверка типов и локальный HTTP-запрос.

В установленном workerd режим `redirect: "error"` вызывает исключение ещё
до отправки запроса, хотя Node.js его принимает. Используется `manual`:
редиректы не выполняются, ответ 3xx останавливает серию как HTTP-ошибка,
а заголовок авторизации не пересылается на другой адрес.
[Описание ручной обработки редиректов](https://developers.cloudflare.com/workers/runtime-apis/request/).

Выборка мала: два разных запроса, одна модель, три повтора на настройку.
Креативность оценена качественно, без независимых рецензентов. Порядок
температур фиксирован и не рандомизирован. Использован идентификатор модели
без отдельного датированного снимка. Поэтому результаты иллюстрируют
конкретные серии, а не универсальную зависимость качества от температуры.
Новый запрос расширил пространство текста, но сам изменил условия опыта;
сравнивать проценты между сценариями как эффект температуры нельзя.

## Выводы по итогам исследования

**В серии с роботами температура изменила прежде всего названия и девизы:**
арифметика верна в 9 из 9 ответов. При нуле было больше повторов, однако
полной идентичности всех ответов не получилось. При `0.7` и `1.2`
вариантов больше, но их количество одинаково. Образные находки встречаются
при `1.2`, а неудачная числовая ассоциация появилась при `0.7`.
Линейного правила «выше температура — лучше творчество и хуже точность»
полученные ответы не подтверждают.

**Сценарий со снами сделал различия деталей и финалов заметнее**, но не
показал монотонного роста креативности. Все обязательные факты и длина
соблюдены, однако новые условия обслуживания возникли при `0` и `0.7`.
Лексическое разнообразие выше при `0.7`, чем при `1.2`, а общий мотив
лунного ремонта повторяется во всех группах. Поэтому ни высокая температура,
ни большое число различающихся слов не гарантируют новых по смыслу идей.

Практические рекомендации ниже — отправные настройки для дальнейшей
проверки на своей задаче, а не доказанный этой малой выборкой рейтинг:

| Температура | Для каких задач пробовать | Что проверять |
| --- | --- | --- |
| `0` | Извлечение данных, классификация, ответы по шаблону, задачи с приоритетом стабильности | Факты и формат; низкая температура не заменяет валидацию и не гарантирует одинаковый текст |
| `0.7` | Учебные объяснения, варианты формулировок, черновики и названия с ограничениями | Соответствие контексту: пример с «пятёркой» показывает, что варианты требуют отбора |
| `1.2` | Мозговой штурм, слоганы, сюжетные идеи и поиск необычных вариантов | Полезность и уместность каждой идеи; выигрыш относительно `0.7` не гарантирован |

Выбирать температуру следует по результатам проверки своей задачи:
оценивать правильность, разнообразие и уместность отдельно, сохранять
несколько повторов и не подменять качество ответа его необычностью.
