# День 32: автоматизация ревью

Исходное условие и объяснение — в [README](../../challenges/day-32-ai-code-review/README.md).

- Локальный сайт 3032: два фиксированных diff, изменения рабочего дерева,
  источники, замечания и экспорт JSON.
- RAG использует документацию и код. Отчёт: summary, findings с категорией,
  серьёзностью, файлом, строкой, объяснением и рекомендацией. Пустой findings
  допустим. Координаты проверяются по новой стороне diff.
- GitHub Action на PR; доверенный base-код читает head как данные.
  Markdown/JSON-артефакт и Job Summary, без комментариев и исполнения PR-кода.
- Форки пропускаются с явным объяснением. Для реальной работы нужны включение
  файлов в base-ветку и Actions Secret. Удалённый запуск отдельно от локальной проверки.
- Приёмка: ошибки бюджета и авторизации, контроль форматирования, проверка
  ложных координат; честное описание найденных и пропущенных проблем.
