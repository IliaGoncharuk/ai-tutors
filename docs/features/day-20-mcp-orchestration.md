# День 20 — оркестрация MCP

Условие, теория, запуск и результаты: [README](../../challenges/day-20-mcp-orchestration/README.md).

## Поведение и приёмка

- Названия, ключи и ссылки задач исключаются до выдачи в MCP и браузер;
  строки обозначены «Задача N». Новые результаты обезличены; правила для старых
  сохранений и границы нумерации — в [ADR 0016](../decisions/0016-tracker-anonymous-results.md).

- Самостоятельный сайт 3020; два реальных MCP-процесса с разными PID.
- `tracker-data`: `search_issues`; `tracker-analytics`: `summarize_issues`,
  `compare_previous`, `save_report`, `get_latest_report`.
- Разделение учебное; оба работают с Трекером. Второй сервер читает локальные
  снимки и не получает токен внешнего API. GitLab не используется.
- Каталог модели объединяется с префиксами серверов. Хост маршрутизирует вызов
  и подставляет локальные идентификаторы; модель их не получает.
- Четыре шаблона запросов: полный отчёт, на сегодня, просроченные, последний отчёт.
- Модель выбирает инструменты в реальном режиме; в демонстрации их выбирает код.
- Полный отчёт: сбор → расчёт → сравнение → сохранение. Последний отчёт требует
  только аналитического сервера. Отсутствие прошлого отчёта явно обозначается.
- Код блокирует нарушение зависимостей и параметры, противоречащие запросу.
  Неизвестный инструмент и ошибка сервера останавливают выполнение.
- Модель получает только числовые показатели и технические результаты, без
  строк задач, ссылок, локальных идентификаторов и путей. Максимум 8 шагов модели.
- Рабочие снимки и отчёты хранятся вне Git; история demo/live раздельна.
- Локальный бюджет учитывает расход по токенам и резервы запросов без известного
  расхода. Успешный ответ со статистикой освобождает свой резерв; перенос старого
  журнала сохраняет счётчики и резервную копию. Подробности — в README.
- Приёмка: разные процессы, несколько маршрутов, порядок, граница данных,
  ошибки, перенос журнала и бюджет, 3 реальных сценария, браузер, типы и сборка.
