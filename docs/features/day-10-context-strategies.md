# День 10: стратегии управления контекстом без summary

Дословное задание — в [README](../../challenges/day-10-context-strategies/README.md#исходное-задание).
2026-09-13 пользователь подтвердил отдельный CLI, локальные проверки и один
реальный эксперимент: до 63 генераций GPT-5.6 Luna с общим лимитом 100000
токенов. Выбор зафиксирован в [решении 0009](../decisions/0009-day-10-context-strategies.md).

## Память и переключение

- `/strategy window|facts|branching` выбирает режим; у режимов отдельные
  сохраняемые диалоги. Переключение возвращает ранее сохранённое состояние
  выбранного режима. Переноса или реконструкции удалённой переписки нет.
- `window`: после каждого успешного хода хранится не более N последних
  отдельных сообщений. N=6 по умолчанию; допустимы чётные числа 2–1000,
  чтобы не разрывать пары user/assistant. Следующий запрос — инструкции,
  последние N сохранённых сообщений и новый вопрос.
- `facts`: перед каждым ответом модель получает прежний словарь, последние
  N сообщений и новое сообщение пользователя. Возвращает только изменения
  атомарных ключей через строгую JSON Schema; `null` удаляет явно отменённый
  факт. Старые значения заменяются, при отсутствии изменений возвращается
  пустой список. Источником фактов служат явные сообщения и подтверждения
  пользователя; хвост нужен для разрешения ссылок. Это правило промпта,
  а не гарантия семантической точности извлечения.
- Facts содержит до 40 ключей и 8000 символов JSON. Ключ — латиница, цифры,
  дефис или подчёркивание, начинается с буквы, до 48 символов; значения —
  строки до 400 символов. Неверный формат, повторные ключи в одном обновлении
  или переполнение словаря отклоняют ход без молчаливого удаления фактов.
  Запрос ответа: инструкции, актуальный facts как справочные данные,
  хвост N сообщений и текущий вопрос. `/facts` показывает словарь режима facts.
- `branching`: `/checkpoint NAME` сохраняет неизменяемую копию истории активной
  ветки. `/branch NAME CHECKPOINT` создаёт ветку от этого снимка;
  `/switch NAME` выбирает её. Имена уникальны, создание не переключает ветку.
  `/branches` показывает доступные ветки и checkpoints. В контекст попадает
  полная история активной ветки; соседние ветки туда не добавляются.
- Summary, compaction, скрытые Conversations и `previous_response_id`
  не используются. `store: false`, `truncation: disabled`; большой вход может
  быть отклонён, ветвление не обещает неограниченной памяти или экономии.

## Хранение и ошибки

Все режимы, N, активная ветка и checkpoints сохраняются одним атомарно
заменяемым JSON: `~/.ai-tutors/day-10/context.json` либо абсолютный
`STRATEGIES_AGENT_FILE`. Одна копия CLI на файл. Повреждённый или несовместимый
файл отклоняется без перезаписи. N задаётся через `--keep=8` при создании
нового файла; при существующем файле и несовпадающем N запуск отклоняется.
`--strategy=facts` выбирает режим также при восстановлении.

Facts и новая пара сообщений фиксируются вместе после успешного ответа.
Ошибка извлечения, ответа или дисковой записи сохраняет прежнюю память.
Параллельные запросы и изменения во время хода отклоняются. `/history` читает
активный диалог; `/reset` очищает все три режима, ветки и checkpoints;
`/exit` завершает CLI. Расход процесса сохраняется после сброса и переключений,
после перезапуска счётчик расхода начинается заново.

## API и измерения

Общий Gateway учитывает все генерации: `answer` (до 768 выходных токенов)
и `facts` (до 512). Модель — `gpt-5.6-luna`, temperature=0, reasoning=none,
verbosity=low, service_tier=default. Автоматических повторов нет, timeout=60 с.
Перед генерацией API считает полный вход, включая JSON Schema; вход с резервом
выхода проверяется по окну модели и оставшемуся общему лимиту 100000 токенов.
В CLI и всей серии сравнения лимит — 63 генерации за процесс/Gateway.

Используется фактический usage; оплаченная неудачная генерация остаётся в
статистике. Отсутствующий usage означает неизвестный расход и блокирует
дальнейшие генерации. `/stats` показывает вход/выход, факты и неизвестные
измерения. Это лимит токенов генераций, не денежный бюджет; стоимость endpoint
подсчёта не оценена. [Тариф модели](https://developers.openai.com/api/docs/models/gpt-5.6-luna)
и [поля usage](https://developers.openai.com/api/reference/typescript/resources/responses/methods/create)
проверены 2026-09-13.

## Сравнение и приёмка

По уточнению пользователя предусмотрена одна команда из корня репозитория:
`npm.cmd --prefix challenges/day-10-context-strategies run check:live`.
Она последовательно выполняет синтаксическую проверку, локальные тесты
и реальное сравнение. Ошибка любого этапа прерывает цепочку с ненулевым
кодом завершения; ошибка локального этапа не допускает платных запросов.
Требуются установленные зависимости и `OPENAI_API_KEY` в окружении.
Выполнение пользователем этой команды запускает новую платную серию.

В конце выводятся таблица и автоматический вывод по текущему прогону:
точное совпадение полей итогового ТЗ, незачтённые поля, общий расход,
накладные расходы facts, сравнение расхода одинаковой траектории и результат
проверки веток. Вывод сохраняется также в новом Markdown-отчёте. Для прерванной
серии, неизвестного usage или нарушения независимости веток итоговый победитель
не определяется. Различия регистра и формулировок могут снижать строгую оценку;
автоматический вывод этого не интерпретирует как доказанную потерю смысла.
Отсутствие ключа обнаруживается до создания каталога результатов.

Канонические входные сообщения и эталоны находятся в
[scenario.mjs](../../challenges/day-10-context-strategies/scenario.mjs).
Методика, все сообщения, фактические ответы и подсчёты раскрываются в
[протоколе](../../challenges/day-10-context-strategies/results/2026-09-13-live/report.md).
Эталоны доступны только локальному оценщику. Все три режима проходят одну
траекторию из 15 пользовательских ходов, контрольные ответы проверяются на шагах
6/11/15; дополнительное продолжение bot измеряется отдельно от основной
траектории web. Один общий префикс branching исполняется и оплачивается один раз.

В JSON протокола сохранены фактические payload генераций, полные ответы,
изменения facts, usage, тайминги и действия с ветками; заголовков авторизации
там нет. Такой полный журнал создаёт только исполнитель фиксированного
синтетического эксперимента; агент не читает его как память. Обычный CLI
не архивирует удалённые сообщения. Отчёт записывается в новый каталог
`results/live-TIMESTAMP`, иной путь — `--out=PATH`; существующий results.json
не перезаписывается. Частичные данные сохраняются после каждого вызова;
прерванная серия не изображается полным сравнением.

Локальные тесты проверяют удаление префикса, обновление/отмену фактов,
независимость веток и checkpoint, переключение режимов, атомарность ошибок,
восстановление двумя процессами, общий бюджет, неизвестный usage и фактический
HTTP-формат SDK с подменой fetch. Симулятор распознаёт ограниченные шаблоны
сценария и использует условный токенизатор; его качество не считается качеством LLM.

Реальный прогон завершён: 63 генерации, 46920 токенов. Содержательная оценка,
расхождения строгого сравнения строк, ограничения и удобство команд — в
[разборе](../../challenges/day-10-context-strategies/results/2026-09-13-live/analysis.md).
Последующие реальные прогоны требуют нового решения пользователя об API-расходах.
