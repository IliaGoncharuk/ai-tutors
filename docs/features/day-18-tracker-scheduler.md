# День 18 — расписание сводок Трекера

Условие и самостоятельное объяснение: [README](../../challenges/day-18-tracker-scheduler/README.md).

## Поведение и приёмка

- Названия, ключи и ссылки задач исключаются до выдачи в MCP и браузер;
  строки обозначены «Задача N». Новые результаты обезличены; правила для старых
  сохранений и границы нумерации — в [ADR 0016](../decisions/0016-tracker-anonymous-results.md).

- Сайт 3018, ручной запуск; отдельный MCP-процесс содержит фоновый исполнитель.
- Инструменты: `schedule_digest`, `run_digest_now`, `get_digest`.
- SQLite вне Git хранит настройки и историю, включая результаты и ошибки.
- По умолчанию 09:00 Asia/Yekaterinburg по будням; пользователь включает расписание.
- Проверка каждые 5 секунд; запуск после пропущенного времени в текущий будний день.
- Уникальность планового результата: источник + дата. Изменение времени не
  повторяет успешный запуск за этот день. Ручные обновления независимы.
- После ошибки до трёх попыток с паузами 1 и 5 минут. При перезапуске незавершённый
  запуск отмечается прерванным и может быть повторён в пределах лимита.
- Старый успешный снимок при ошибке сохраняется; его время показано явно.
- Только назначенные мне задачи без резолюции. Источники demo/live изолированы.
- Закрытие вкладки не останавливает работу; выход из приложения или сон компьютера
  останавливает её. Модель не вызывается; Трекер не изменяется.
- Приёмка: таймер без HTTP, границы расписания, перезапуск полного приложения,
  ограничение повторов, реальное чтение Трекера, HTTP, типы и сборка.
