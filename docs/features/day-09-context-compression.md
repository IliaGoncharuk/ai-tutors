# День 9: управление контекстом

Исходное условие и краткое объяснение — в [README задания](../../challenges/day-09-context-compression/README.md).
2026-09-13 пользователь подтвердил отдельный CLI и локальные проверки.
Реальный API-запуск не входит в это разрешение. Выбор — в
[решении 0008](../decisions/0008-day-09-cli-context-compression.md).

## Поведение

1. Агент работает с `gpt-5.6-luna` через Responses API. N=6 и интервал=10
   настраиваются чётными положительными числами: считаются отдельные сообщения,
   пары user/assistant не разрываются. Первое сжатие — перед шестым вопросом.
2. Когда после последнего сжатия накопился интервал новых сообщений и есть
   сообщения старше N, агент отправляет прежнее summary и старую часть отдельным
   запросом к модели. В обычный запрос идут инструкции, summary как справочные
   данные, свежие сообщения и текущий вопрос; скрытая полная история через
   `previous_response_id` или Conversations не подключается.
3. Сразу после сжатия остаются N прежних сообщений дословно. После успешного
   ответа добавляется новая пара. Между сжатиями несжатая часть растёт; N —
   гарантированно сохраняемый хвост, а не жёсткий размер на каждом шаге.
4. Summary, свежие сообщения, число сжатых сообщений и счётчик интервала
   находятся в отдельных полях одного JSON. Запись атомарная; история не
   архивируется. Ошибка summary, ответа или записи не фиксирует ни сжатие,
   ни новый ход. Уже потраченные токены остаются в статистике процесса.
5. Путь по умолчанию — `~/.ai-tutors/day-09/context.json`; переопределение —
   абсолютный `CONTEXT_AGENT_HISTORY_FILE`. Режим `--full` использует
   `full-history.json` и отвергает файл с уже сжатой памятью. Один процесс на файл.
6. `/summary`, `/history`, `/stats`, `/reset`, `/exit` работают локально.
   `/reset` очищает память на диске, сохраняя расход процесса; после перезапуска
   восстанавливается память, статистика начинается заново.
7. Перед генерацией API считает вход; перед сжатием также измеряется прежний
   полный запрос для сравнения. Для ответов резервируется 256 токенов, для
   summary — 384; вход с резервом проверяется по окну модели. Автоматического
   удаления сообщений нет (`truncation: disabled`), сохранение Responses
   отключено (`store: false`). Огромное сообщение может не поместиться даже
   после сжатия; это не механизм неограниченного контекста.
8. Журнал отдельно учитывает answer/summary и суммирует фактический usage,
   включая незавершённые ответы. Нет usage — расход неизвестен. Лимит генераций
   текущего процесса/режима сравнения — 250000 токенов с резервом полного выхода
   очередного вызова; при неизвестном расходе дальнейшая генерация блокируется.
   Это не денежный бюджет; биллинг endpoint подсчёта не оценивается.

## Сравнение и приёмка

- Два независимых агента проходят одинаковые 20 пользовательских сообщений,
  с одинаковой моделью, температурой 0 и лимитами. Ответы каждого агента
  попадают только в его историю. Ожидания оценщика никогда не отправляются модели.
- Четыре вопроса проверяют восемь полей: проект, актуальный бюджет, срок,
  точный код, запрет платных сервисов, актуальный формат, резерв и остаток.
  Это проверка фактов и ограничений, а не универсальная оценка качества текста.
- Отчёт выводит контрольные ответы, ошибки, вход по ходам, расход ответов,
  расход summary и чистую экономию. Для прерванных серий или неизвестного usage
  процент экономии не рассчитывается. Короткий контекст может дать перерасход.
- Локальный симулятор читает только переданный контекст и использует условный
  токенизатор. Тест с намеренно потерянным кодом должен снижать оценку; успех
  симуляции не доказывает качество реальной модели.
- Перехват SDK проверяет фактические HTTP payload и usage без внешних запросов.
  Тесты также проверяют границы интервала, точность хвоста, повторное summary,
  ошибки, лимиты, неизвестный usage, сброс, повреждённый JSON и два процесса.
- `npm run demo` работает без ключа. `npm run demo:live` выполняет до 43 генераций
  без автоматических повторов и дополнительные подсчёты; данные сравнения
  остаются в памяти процесса и выводятся в терминал. Реальный запуск требует
  отдельного разрешения на API-расходы.
