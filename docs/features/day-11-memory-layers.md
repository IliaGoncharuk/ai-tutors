# День 11: локальная лаборатория памяти агента

## Условие и границы

Дословное условие находится в
[README Дня 11](../../challenges/day-11-memory-layers/README.md#исходное-задание).
Нужно раздельно хранить текущий диалог, данные задачи и долговременные сведения,
явно выбирать место записи и показывать влияние памяти на ответы.

Пользователь утвердил замену прежнего CLI локальным сайтом, удаление старого
решения без архива, реальные API-проверки и последовательное выполнение
дней 11–15 в отдельных каталогах. День 11 — самостоятельное приложение;
оно не импортирует исполняемый код других заданий. Выбор и альтернативы —
в [решении 0010](../decisions/0010-day-11-memory-layers.md).

## Пользовательский сценарий

Пользователь открывает локальный сайт, переписывается с агентом и рядом видит
три слоя памяти. Для рабочей или долговременной записи он выбирает слой,
задаёт ключ и значение и сохраняет их отдельным действием. Просьба «запомни»
в обычном сообщении сама по себе не переносит данные в другой слой.

Можно начать новый диалог, создать новую задачу, продолжить сохранённую работу,
посмотреть фактический контекст запроса и сравнить четыре ответа при разном
составе памяти. Данные примера загружаются только явным действием пользователя.

## Слои и запись

| Слой | Назначение | Файл в опубликованной версии данных | Когда меняется |
| --- | --- | --- | --- |
| Краткосрочная память | Последние 6 сообщений активного диалога | `sessions.json` | После обычного завершённого обмена вопросом и ответом |
| Рабочая память | Явно сохранённые данные выбранной задачи | `tasks.json` | При сохранении, изменении или удалении записи пользователем |
| Долговременная память | Профиль, принятые решения и знания для последующих задач | `long-term.json` | При явном действии пользователя |

`system.json` содержит служебный выбор и журнал действий; это не четвёртый слой
знаний агента. В запрос включаются данные только активной задачи и её диалога.
Обычный ответ модели не изменяет рабочие или долговременные записи.

Новый диалог начинается с пустой краткосрочной памятью и сохраняет рабочие
и долговременные сведения. Новая задача получает пустые рабочую и краткосрочную
память; долговременные сведения остаются доступными. Продолжение сохранённой
работы восстанавливает соответствующее состояние вместо повторного ввода условий.

Удаление записи из одного слоя не означает удаления её копий из других слоёв.
Например, старое сообщение может повторять удалённое предпочтение. Для проверки
ответа без такой копии нужно также начать новый диалог.

## Хранение и восстановление

Каталог по умолчанию — `~/.ai-tutors/memory-lab-day-11/`, вне публичного
репозитория. Каждая запись создаёт согласованную версию раздельных JSON-файлов;
`CURRENT.json` переключается на неё после подготовки файлов. Чтение использует
только опубликованную версию. Такое устройство не позволяет восстановить
сочетание старого диалога и новых данных задачи после незавершённой записи.

JSON — открытый текст, а не зашифрованное хранилище. Учебные протоколы должны
содержать вымышленные данные; правила обращения с ключом и личной информацией —
в [ограничениях проекта](../agent/CONSTRAINTS.md#публичность-и-чувствительные-данные).

## Контекст и обращения к модели

Сервер собирает запрос из инструкций приложения, выбранных слоёв памяти
и вопроса пользователя. Интерфейс показывает фактические данные, передаваемые
в API: наличие факта на диске и его включение в запрос — разные проверки.
Память передаётся как данные, а не как произвольные системные инструкции.

Используется OpenAI Responses API и модель `gpt-5.6-luna`; лимит ответа —
1200 токенов. API-ключ поступает только из серверной переменной окружения
`OPENAI_API_KEY`. Браузер обращается к локальному серверу и не получает ключ.
Для независимой локальной памяти контекст формируется приложением; механизм
передачи истории описан в
[официальной документации](https://developers.openai.com/api/docs/guides/conversation-state).

По умолчанию выбран реальный API: отправка вопроса или запуск сравнения
передаёт OpenAI вопрос и включённые данные памяти и расходует API-токены.
Расход показывается по `usage` ответа. Режим демонстрации включается отдельно
и явно помечается как симуляция; его ответы не являются измерением модели.
Отсутствие ключа или ошибка API не должны незаметно подменять ответ симуляцией.

## Методика сравнения

Перед сравнением фиксируется один снимок памяти и один вопрос. Выполняются
четыре независимых запроса: все слои; без краткосрочного; без рабочего;
без долговременного. Отключённый слой полностью исключается из контекста.
Ответы сравнения не записываются в диалог и не участвуют в следующих вариантах.

Проверка различает три свойства: корректность хранения, фактический состав
запроса и использование доступных сведений моделью. Для неизвестного факта
ожидается признание отсутствия данных, а не догадка. Успешная запись на диск
сама по себе не доказывает качество ответа. Даже ограничение структуры ответа
не гарантирует правильности его содержания:
[Structured Outputs, Handling mistakes](https://developers.openai.com/api/docs/guides/structured-outputs#handling-mistakes).

`npm run experiment:live` выполняет шесть реальных запросов на вымышленных
данных из действия `seed`: четыре состава памяти, новый диалог и новая задача.
В рабочем слое — проект сервиса записи к репетиторам, занятие 45 минут
и веб-приложение; в долговременном — русский язык и `Asia/Yekaterinburg`;
в подготовленном диалоге — акцент на отмене занятия. Исходный диалог задан
явно и не требует дополнительного вызова модели.

Вопрос требует JSON с `project`, `minutes`, `delivery`, `language`, `timezone`
и `focus`. Оценщик сравнивает шесть значений и их типы с независимым эталоном,
включая `null` для отсутствующих данных. Для разбора допускается удаление
обрамляющего Markdown-блока; оценка не является строгой проверкой формата
вывода без Markdown. Каждая из шести проверок использует исходный снимок
или его независимое преобразование, а не ответ предыдущей проверки.

Исполнитель —
[scripts/experiment.mjs](../../challenges/day-11-memory-layers/scripts/experiment.mjs).
Он записывает исходное состояние, точный вопрос, инструкции, сообщения,
ответы, поэлементную оценку и расход в `results/live/results.json`, краткий
отчёт — в `results/live/report.md`. Повторный запуск заменяет оба файла.
Результаты реальной серии от 20 сентября и разбор её единственного
содержательного расхождения приведены в
[README](../../challenges/day-11-memory-layers/README.md#результаты-и-выводы).

## Приёмка

1. Сайт запускается одной командой и показывает чат и три раздельных слоя.
2. Обычная переписка меняет только краткосрочную память; ручное сохранение
   изменяет выбранный слой.
3. Новый диалог сохраняет данные задачи и долговременную память; новая задача
   не получает рабочие сведения предыдущей.
4. Перезапуск восстанавливает опубликованное состояние; незавершённая запись
   не становится текущей версией данных.
5. Контекст показывает реальные передаваемые сведения, а сравнение использует
   один исходный снимок и не меняет диалог.
6. Реальный режим и симуляция различаются явно; ключ не попадает в браузер
   и файлы проекта.
7. Проходят локальные тесты, проверка TypeScript и сборка; реальный эксперимент
   сохраняет наблюдаемые ответы, включая возможные ошибки модели.

Команды запуска и статус проверок — в README. Предыдущие результаты CLI
не считаются результатами нового сайта.
