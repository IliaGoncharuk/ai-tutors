# День 2 — управление ответом через API

## Условие

Один и тот же запрос отправить без ограничений задания и с явным форматом,
ограничением длины и условием завершения (stop sequence либо инструкция).
Сравнить полученные ответы.

## Согласованная реализация

Kotlin/JVM + Compose Desktop, одно окно и две колонки. Оба запроса стартуют
параллельно, текст выводится по поступлению событий OpenAI Responses API.
Пользователь выбрал desktop и компактный код с комментариями; приложение
находится в одном Kotlin-файле, тесты отдельно.

В обеих ветках одинаковые `input`, модель, инструкция отвечать по-русски,
`stream: true`, `store: false` и `reasoning.effort: none`. История предыдущей
генерации не передаётся. Отличаются только дополнительные инструкции и бюджет:

| Условие | Слева | Справа |
| --- | --- | --- |
| Формат | Не задан | Выбор: нумерованный список, список с тире, один абзац |
| Количество пунктов | Не задано | Ползунок 1–8, по умолчанию 3; отключён для абзаца |
| Длина в словах | Не задана | Ползунок 20–300 с шагом 10, по умолчанию 90, включая маркер |
| Завершение | Не задано | Выбор отдельной строки `КОНЕЦ`, `ГОТОВО`, `END`, без текста после неё |
| `max_output_tokens` | 2048, технический потолок | Ползунок 128–2048 с шагом 128, по умолчанию 512 |

«Без ограничений» означает без ограничений задания, не бесконечный бюджет.
Маркер — инструкция модели, не серверный параметр `stop` и не локальная обрезка.

## Приёмка

- Вопрос общий, пустой вопрос блокирует запуск. Модель выбирается из списка
  `gpt-5.6-luna`, `gpt-5.6-terra`, `gpt-5.6-sol`, по умолчанию первая;
  произвольный ввод исключён. Список локальный, доступность аккаунту не проверяет.
- Ограничения настраиваются регуляторами над правым ответом, без текстового
  редактора инструкции. Приложение собирает её из выбранных значений.
- Одна кнопка запускает два независимых запроса; до окончания обоих повторный
  запуск и изменение полей недоступны.
- Обе колонки видны одновременно, текст постепенно дописывается; его можно выделять.
- Ошибка одной ветки не отменяет вторую. Полученный частичный текст сохраняется.
- Отображаются статус и входные/выходные токены из API. Отсутствующий usage — `—`, не ноль.
- `incomplete` с причиной лимита отличается от `completed`; EOF без финального
  события не считается успехом. Отказ модели помечается отдельно.
- Проверка использует снимок настроек запуска; перемещение ползунка после
  ответа не меняет его оценку. Новые настройки применяются при следующем запуске.
- Локальная проверка формата требует выбранное число непустых строк с
  последовательной нумерацией либо префиксом `- `, или одну строку без префикса
  списка для абзаца. Конечный маркер проверяется отдельно и исключается из
  проверки структуры. Перенос по ширине окна не считается новой строкой.
- Слова считаются как группы букв/цифр, соединённые дефисом/апострофом;
  номера пунктов исключаются, выбранный маркер включается. Это операционное правило, не
  универсальное лингвистическое определение слова.
- Проверки не исправляют и не обрезают исходный ответ. Их галочки отражают
  только текстовые условия, а не истинность ответа или успешность API.
- Без ключа отображается объяснение, запросы не отправляются. Ключ берётся
  только из окружения; ответы не пишутся на диск приложением.
- Индикатор ключа показывает наличие непустой переменной в текущем процессе,
  не её значение и не действительность ключа в OpenAI.
- Закрытие окна отменяет запросы и освобождает соединения.
