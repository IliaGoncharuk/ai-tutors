# День 7: сохранение контекста

## Условие и учебная цель

Хранить историю диалога (`messages`) в JSON или SQLite, загружать её при
перезапуске приложения и продолжать разговор с учётом прошлых сообщений.
Практическая проверка: начать диалог, полностью перезапустить приложение,
продолжить и убедиться, что агент помнит прошлый контекст.

## Поведение

1. Отдельный CLI Дня 7 использует JSON. Путь по умолчанию находится вне
   репозитория и не зависит от рабочей директории; абсолютный путь можно
   переопределить переменной `AGENT_HISTORY_FILE`.
2. `Agent` загружает историю из хранилища при создании. Отсутствие файла означает
   новый диалог; повреждённый или недоступный файл приводит к ошибке без очистки.
3. Каждый запрос содержит все сохранённые сообщения `user` и `assistant`,
   затем новое сообщение пользователя. API-ключ не является частью истории.
4. После успешного завершённого непустого ответа оба сообщения сохраняются
   вместе. Основной JSON заменяется после полной записи временного файла.
5. Память обновляется и ответ выводится после успешной записи. Ошибки API,
   проверки ответа или записи не меняют предыдущую память.
6. `/history` показывает диалог, `/reset` очищает его в памяти и на диске,
   `/exit` завершает приложение. Неудачный сброс сохраняет прежний контекст.
7. JSON версии 1 хранит только массив полных пар сообщений с ролями и текстом.
   Частичные ходы, ключи, настройки клиента и объекты ответа API не сохраняются.
8. Один файл обслуживает один процесс. Нескольким одновременным агентам нужны
   разные файлы. Ограничение размера, compaction, шифрование и резервные копии
   в область задания не входят.

## Критерии приёмки

- Первый процесс CLI выполняет успешный ход и завершается; JSON содержит два
  сообщения.
- Второй процесс с тем же файлом восстанавливает два сообщения, даже если
  запущен из другой рабочей директории.
- Новый вопрос без повторения проверочного слова получает ответ с этим словом;
  итоговый JSON содержит прежнюю пару без изменений и новый полный ход.
- Тест с перехватом API-запроса подтверждает точный порядок всей истории.
- `/reset` переживает перезапуск; следующий диалог начинается с пустого контекста.
- Повреждённый файл не затирается, ошибка чтения не выдаётся за пустую историю,
  ошибка API или записи не уничтожает последнюю успешную переписку.
- Тесты и `npm run demo` не требуют ключа и не выполняют платных вызовов.
  `npm run demo:live` повторяет сценарий с двумя реальными API-запросами.
- README объясняет запуск, формат данных, проверку перезапуска, ошибки и
  ограничения. Фактически выполненные проверки и их границы указаны явно.
