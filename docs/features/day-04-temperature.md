# День 4 — температура

## Условие и учебная цель

Выполнить один и тот же запрос при `temperature = 0`, `0.7` и `1.2`.
Сравнить точность, креативность и разнообразие ответов, определить подходящие
задачи для каждой настройки. Результат — реальные примеры и выводы.

## Согласованная реализация

Пользователь 2026-09-05 выбрал девять платных API-вызовов: по три повтора
на каждую температуру. Дополнительно запросил в README описание задания,
справочную информацию и выводы в конце документа.

Локальный Node.js-скрипт находится в `challenges/day-04-temperature`.
Выбор скрипта и альтернативы описаны в [решении 0004](../decisions/0004-day-04-script.md).
CLI не требует сторонних зависимостей. Точные запросы и параметры задаются в
[`core.mjs`](../../challenges/day-04-temperature/core.mjs)
и сохраняются с каждым результатом. Задача сочетает проверяемый расчёт числа
роботов и придумывание названий и девиза. Позднее в тот же день пользователь
согласовал локальный веб-интерфейс, второй творческий сценарий и ещё девять
платных вызовов. Второй сценарий — объявление мастерской снов с тремя
обязательными фактами, одним способом ремонта, заголовком, неожиданным финалом
и длиной 80–120 слов. Всего в двух сохранённых сериях 18 вызовов.

Запросы идут последовательно тремя кругами `0 → 0.7 → 1.2` без общей истории.
Постоянны модель `gpt-5.6-luna`, инструкция, запрос, лимит 600 выходных токенов,
`reasoning.effort: none` и `store: false`; `top_p` не передаётся.
Скрипт сохраняет тексты, статусы, параметры, токены и длительность в JSON
и формирует Markdown-протокол. Перед новым вызовом результат предыдущего
записывается на диск. Ошибка, пустой/незавершённый ответ или несовпадение
температуры в ответе API останавливают эксперимент без повторов.

## Веб-интерфейс

В `challenges/day-04-temperature/web` находится локальное React/Vinext-приложение.
Сервер запускается на `http://localhost:3004/`. В нём два сценария, три колонки
температур и общий выбор повтора. При открытии загружается сохранённая серия
с роботами, серия со снами также доступна без API. Отображаются ответы,
текстовые проверки, число слов, токены, длительность и разнообразие.
Сохранённые данные явно помечены «Сохранённый эксперимент» с датой;
серия, начатая кнопкой, помечена «Текущий запуск».

Кнопка запуска явно указывает девять платных запросов. Сервер использует тот же
исполнитель, что CLI, и передаёт снимки результатов потоком NDJSON после каждого
ответа. Одновременный второй запуск в том же процессе отклоняется; допускаются
только запросы с локальной страницы того же origin. Закрытие потока отменяет
дальнейшую работу после обнаружения разрыва, но не гарантирует отсутствия платы
за уже отправленный вызов. Ошибки сохраняют полученную часть серии в интерфейсе.

Веб-результаты находятся в памяти страницы и скачиваются в Markdown/JSON;
сервер их на диск не пишет. CLI сохраняет на диск. Обе сохранённые исследовательские
серии остаются доступны кнопкой восстановления. Ключ читается только сервером
из окружения и не включается в клиентский код или production-сборку.

## Оценка

- Точность проверяется чтением каждого ответа: итог `15`, верное вычисление,
  три разных названия, короткий девиз, отсутствие новых численных фактов.
- Креативность оценивается качественно по названиям и девизам с конкретными
  примерами. Баллы без формальной шкалы и отдельная модель-судья не используются.
- Скрипт считает различные полные тексты после нормализации пробелов.
  Содержательное разнообразие названий и девизов оценивается отдельно в README.
- Для снов текстовые проверки ищут название, `19:00`, основу «бесплатн» и
  считают слова. Это признаки, а не доказательство отсутствия противоречий.
  Новые условия обслуживания и качество финала проверяются чтением.
- Дополнительная метрика — среднее расстояние Жаккара наборов слов по трём
  парам повторов; её формула и подсчёт слов описаны в README. Это лексическое,
  а не смысловое разнообразие. Общая реализация — `assessment.mjs`.
- Три повтора одной простой задачи дают иллюстрацию, а не статистическое
  доказательство превосходства настройки. Рекомендации отделяются от наблюдений.

## Приёмка

- Сохранены две серии по девять завершённых реальных ответов: по три на каждую
  температуру внутри каждого сценария.
- По JSON можно проверить постоянство параметров и восстановить тексты.
- README содержит описание задания, справку с первичными источниками,
  инструкции запуска, сравнение и завершается выводами по исследованию.
- Просмотр `--dry-run` и тесты не делают сетевых вызовов; платный запуск
  требует `--run --output <каталог>` и `OPENAI_API_KEY` в окружении.
- Уже существующий `results.json` не перезаписывается; при его наличии
  новые запросы не отправляются.
- Локальные тесты проверяют серию запросов, обработку ошибок, сохранение
  результатов и отсутствие ключа в артефактах.
- Веб-интерфейс показывает сохранённые данные без расходов, позволяет выбрать
  сценарий и повтор, запустить серию и скачать полные/частичные результаты.
- Проходят локальные тесты, линтер, проверка типов, сборка и HTTP-проверки.
- Отдельный тест в workerd проверяет весь поток с подменой API и настоящий
  Request. Используется `redirect: manual`; HTTP 3xx останавливает серию.
- Правила обращения с ключом — в [CONSTRAINTS](../agent/CONSTRAINTS.md).
  Публикация и дополнительные платные запуски не входят в выполненную серию.

Фактические результаты и их интерпретация находятся в
[README задания](../../challenges/day-04-temperature/README.md).
