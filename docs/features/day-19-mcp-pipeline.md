# День 19 — композиция MCP-инструментов

Исходное условие и описание: [README](../../challenges/day-19-mcp-pipeline/README.md).

## Поведение и приёмка

- Названия, ключи и ссылки задач исключаются до выдачи в MCP и браузер;
  строки обозначены «Задача N». Новые результаты обезличены; правила для старых
  сохранений и границы нумерации — в [ADR 0016](../decisions/0016-tracker-anonymous-results.md).

- Отдельный сайт 3019; цепочка фиксирована программой, без языковой модели.
- Один MCP-сервер: `search_issues` → `summarize_issues` → `save_report`.
- Первый шаг читает мои задачи, второй рассчитывает по сохранённому снимку,
  третий сохраняет конкретную сводку. Между шагами передаются проверяемые UUID.
- На сайте видны состояние, длительность, вход и выход каждого шага.
- Ошибка останавливает цепочку; последующие стадии отмечаются пропущенными.
- Повторное сохранение одной сводки не создаёт новый отчёт.
- JSON и Markdown хранятся вне Git, источник и время сбора указаны явно.
- Реальные и учебные данные различаются; смена источника очищает текущий запуск.
- Приёмка: настоящий MCP, проверка передачи данных, оба файла, отказ на обход
  путей и ошибка среднего шага; реальное чтение Трекера, типы и сборка.
