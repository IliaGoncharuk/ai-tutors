# День 6: первый агент

## Условие и учебная цель

Программа должна принять запрос пользователя, передать его LLM через API,
получить ответ и вывести его в простом интерфейсе. Агент должен быть отдельной
сущностью, а не одиночным вызовом API: внутри него инкапсулированы политики,
память, формирование запроса и обработка ответа.

## Принятое поведение

1. Пользователь общается с агентом через интерактивный CLI.
2. Входная политика проверяет и нормализует сообщение.
3. Агент хранит всю переписку текущего процесса в собственной памяти.
4. Каждый запрос содержит полную историю ролей `user` и `assistant`.
5. Выходная политика принимает только завершённый непустой ответ.
6. Неуспешный ход не изменяет историю.
7. `/reset` очищает память, `/exit` завершает CLI.
8. Каждый экземпляр `Agent` изолирован и может иметь отдельную конфигурацию.
9. Judge не используется, потому что критерий не требует оценки или выбора
   ответа.

История не сохраняется на диск и исчезает после завершения процесса. API-ключ
читается из `OPENAI_API_KEY`; реальное значение не хранится в репозитории.

## Критерии приёмки

- CLI принимает сообщения и показывает текст ответа LLM.
- `Agent` является отдельным классом и самостоятельно вызывает Responses API.
- CLI не формирует API-запрос и не управляет историей.
- Второй запрос включает первый успешный обмен сообщениями.
- Входная и выходная политики выполняются внутри агента.
- Ошибка API или непригодный ответ не повреждают память.
- Конфигурация и состояние не глобальны, поэтому возможно создать произвольное
  число независимых экземпляров.
- Тесты не требуют API-ключа и не выполняют платные вызовы.
- README объясняет устройство агента, политики, память, judge, масштабирование,
  запуск и правила безопасности.
