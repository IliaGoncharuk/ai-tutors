# День 3 — разные способы рассуждения

## Условие и учебная цель

Одну логическую, алгоритмическую или аналитическую задачу нужно решить через
API четырьмя способами: прямым запросом, запросом с инструкцией «решай
пошагово», решением через предварительно созданный моделью промпт и группой
экспертов. Полученные решения сравниваются по различиям и точности.

## Согласованная реализация

Локальное веб-приложение находится в
`challenges/day-03-reasoning-comparison`. Выбор интерфейса и альтернативы
зафиксированы в [решении 0003](../decisions/0003-day-03-local-web.md).

Используется фиксированная задача о числе путей по сетке 5 × 5. Старт — `(1,1)`,
финиш — `(5,5)`, разрешены шаги только вправо и вниз, клетки `(2,2)`, `(3,4)` и
`(4,2)` заблокированы. Эталон `10` вычисляется локально динамическим
программированием и проверяется тестом.

| Способ | Запросы | Отличие промпта |
| --- | ---: | --- |
| Прямой ответ | 1 | Только условие задачи |
| Пошагово | 1 | После условия добавлено «Решай пошагово» |
| Метапромпт | 2 | Первый запрос создаёт промпт без решения, второй решает по нему |
| Группа экспертов | 1 | Аналитик, инженер и критик решают независимо |

Успешный эксперимент выполняет пять платных запросов. Прямой, пошаговый,
экспертный и первый метазапрос стартуют параллельно; второй метазапрос ждёт
созданный промпт. Сбой одной ветки не удаляет результаты остальных.

Во всех решающих запросах совпадают выбранная модель, developer-инструкция
отвечать по-русски без внешних инструментов, `temperature: 0.2`, лимит 900
выходных токенов, `reasoning.effort: none` и `store: false`. Первый метазапрос
имеет отдельный технический лимит 600 токенов. Модели выбираются только из
`gpt-5.6-luna`, `gpt-5.6-terra` и `gpt-5.6-sol`; наличие в списке не гарантирует
доступность конкретному API-проекту.

## Сравнение и ограничения оценки

- Для первых трёх способов итогом считается последнее целое число в тексте.
- Для группы отдельно извлекаются ответы аналитика, инженера и критика по
  заданным маркерам; способ верен, только если верны все трое.
- «Наиболее точный» означает максимальную долю совпавших с эталоном итогов.
  Несколько способов могут разделить первое место.
- Различие ответов определяется по нормализованному полному тексту.
- Автоматическая проверка оценивает конечное число, а не логическую
  безупречность объяснения. Вывод относится к одному запуску, не ко всем
  задачам и не к методу вообще.

## Приёмка

- Первый экран показывает условие, схему сетки, выбор общей модели и
  предупреждение о пяти платных вызовах.
- Одна кнопка запускает четыре стратегии; во время выполнения повторный запуск
  и смена модели недоступны.
- Видны четыре решения, использованные промпты, созданный метапромпт, статусы,
  длительность и input/output tokens.
- Ошибка отдельного способа отображается в его карточке без утраты успешных
  результатов.
- Итог сообщает, различаются ли тексты, сколько способов верны и есть ли
  единственный победитель или ничья.
- Markdown-экспорт содержит задачу, модель, промпты, решения, метрики и
  сравнение; сервер ответы на диск не пишет.
- Без ключа запросы не отправляются и пользователь получает понятное сообщение.
- `OPENAI_API_KEY` доступен только серверному runtime и не попадает в исходники
  или production-сборку.
- Тесты, линтер и production-сборка проходят без реальных API-вызовов.
