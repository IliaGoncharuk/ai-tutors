# Как управлять ответом LLM через API

Справочная статья ко второму занятию. Проверка официальной документации:
2026-09-03. Примеры относятся к OpenAI; параметры других API могут отличаться.

## Главная идея

Запрос к модели содержит не только вопрос, но и требования к результату.
«Объясни HTTP» задаёт тему. «Объясни HTTP тремя пунктами, не более 90 слов»
задаёт ещё и способ подачи. Это полезно, когда результат нужно показать в
карточке интерфейса, прочитать за минуту или передать другой программе.

В интерфейсе не нужно писать инструкции руками: формат и маркер выбираются
из списков, количество пунктов, слова и токены задаются ползунками справа.
Приложение составляет инструкцию по этим значениям. По умолчанию остаётся
пример с тремя пунктами, 90 словами и маркером `КОНЕЦ`.

В нашем эксперименте основной вопрос одинаков. Мы меняем ограничения ответа,
а не предмет разговора. [Точные параметры двух веток](../features/day-02-response-control.md)
зафиксированы отдельно, чтобы статья не дублировала спецификацию приложения.

## Три независимых вопроса

| Что контролируем | Пример | Что проверять после ответа |
| --- | --- | --- |
| Формат | Три нумерованных пункта | Структуру, порядок, лишний текст |
| Длину | Не более 90 слов | Реальный объём по выбранному правилу подсчёта |
| Завершение | Последняя строка `КОНЕЦ` | Наличие маркера и отсутствие продолжения |

Эти требования не заменяют друг друга. Три пункта могут быть очень длинными.
Короткий текст может нарушать формат. Маркер в середине ответа не означает,
что модель действительно остановилась на нём.

## Мягкие требования и технические ограничения

Инструкция естественным языком описывает желаемое поведение. Она не является
проверкой в Kotlin: модель может написать лишний пункт или превысить число слов.
Поэтому полезно разделять три действия: попросить, получить исходный ответ,
проверить его. В демонстрации нельзя незаметно обрезать результат и затем
утверждать, что модель выполнила требование.

`max_output_tokens` — верхний бюджет генерации Responses API. Он включает
видимый вывод и reasoning-токены. При исчерпании бюджета ответ может иметь
статус `incomplete` и причину `max_output_tokens`. Это не команда «закончи
мысль красиво». [Описание параметров Responses](https://developers.openai.com/api/reference/cli/resources/responses/methods/create)

Практическая комбинация: просить короткий содержательно завершённый текст и
оставлять технический запас токенов. Слишком маленький запас способен оборвать
ответ раньше третьего пункта или маркера.

### Почему слова не равны токенам

Токен — единица представления текста моделью, а не обязательно целое слово.
Приложение считает слова локально, API возвращает собственную статистику
токенов. Это разные метрики. Для русского текста нельзя заменять лимит слов
одним фиксированным коэффициентом пересчёта.

В нашем коде правило подсчёта специально определено и протестировано:
буквенно-цифровые группы, без номеров пунктов, но с маркером. Если преподаватель
или продукт использует другое правило, сравнивать нужно по нему.

## Как завершать ответ

### Явная инструкция

Пример требования: «После последнего пункта напиши отдельной строкой КОНЕЦ.
После этой строки ничего не пиши».

Это выбранный нами вариант. Маркер остаётся виден пользователю, а программа
проверяет его положение. Если модель продолжила текст, это нарушение, которое
нужно показать. Само присутствие слова `КОНЕЦ` не управляет сетевым соединением.

### Stop sequence

В Chat Completions параметр `stop` задаёт последовательности остановки,
если выбранная модель их поддерживает. Документация описывает до четырёх
последовательностей; сама последовательность не включается в возвращаемый
текст. Поддержка зависит от модели, её нужно проверять.
[Параметры Chat Completions](https://developers.openai.com/api/reference/cli/resources/chat/subresources/completions/methods/create)

Условный фрагмент JSON для совместимого Chat Completions-запроса:

```json
{ "stop": ["<END>"] }
```

Это не готовый запрос и не параметр нашего приложения. В опубликованной схеме
Responses API `stop` не перечислен. Нельзя переносить настройки между API
только потому, что они вызывают похожие модели.
[Схема Responses](https://developers.openai.com/api/reference/cli/resources/responses/methods/create)

Для stop-маркера стоит выбирать редкую последовательность: распространённое
слово может встретиться внутри полезного ответа. А локальное удаление текста
после маркера вообще не равно остановке генерации на сервере: уже полученные
токены от этого не исчезнут.

## Формат: инструкция, JSON и схема

Просьба «напиши JSON» задаёт желаемый формат словами. JSON mode добавляет
гарантию синтаксического JSON для обычного успешного ответа, но не нужных полей.
Structured Outputs с JSON Schema контролирует структуру: например, обязательные
поля и типы. Для Responses это задаётся через `text.format`. При этом всё равно
нужно обрабатывать отказ модели и незавершённый ответ.
[Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)

Выбор зависит от потребителя: человеку удобны пункты, программе — объект с
известными полями. Валидная схема не доказывает истинность содержимого.
Для этого занятия текстовый формат оставлен намеренно: нарушения хорошо видны,
и их можно обсудить, не смешивая эксперимент с отдельной темой JSON Schema.

## Что делает Kotlin-код

В [Main.kt](../../challenges/day-02-response-control/src/main/kotlin/Main.kt)
нет слоёв сервисов и репозиториев: задача небольшая, и её удобно читать сверху вниз.

- `Controls.instructions()` собирает требование из регуляторов; `Choice()` и
  `Dial()` рисуют списки и ползунки.
- `payload()` создаёт JSON запроса. `input` сохраняет один вопрос, а `instructions`
  дополняется правилами только для правой колонки.
- `events()` превращает SSE-события OkHttp в `Flow<String>`.
- `accept()` добавляет фрагмент текста или обновляет статус и usage.
- `words()` и `checks()` проверяют уже полученный текст.
- `App()` создаёт окно, хранит состояние и запускает две корутины.

Ключевой фрагмент управления запросом:

```kotlin
put("model", model)
put("input", prompt)
put("stream", true)
put("max_output_tokens", if (controlled) controls.maxTokens else 2048)
```

Это выдержка из `payload()`, а не самостоятельная программа. `controls` —
снимок выбранных ограничений. Тот же снимок используется для проверки ответа,
поэтому новые положения регуляторов не переоценивают предыдущий результат.
Потолок слева нужен для ограничения расходов: «без ограничений задания» не
означает «без каких-либо технических лимитов».

### Как появляется постепенный текст

При `stream: true` Responses API передаёт Server-Sent Events. Текст приходит
событиями `response.output_text.delta`; окончание всего ответа обозначается
финальным событием, например `response.completed`.
[Streaming Responses](https://developers.openai.com/api/docs/guides/streaming-responses)

В приложении обработка каждого события обновляет состояние соответствующей
колонки. Compose перерисовывает её. Готовый ответ не разбивается искусственно
на буквы, поэтому размер и ритм фрагментов определяет API и сеть.

Сетевые callbacks выполняются вне UI, а `collect` — в корутине интерфейса.
Это позволяет окну оставаться отзывчивым. `supervisorScope` изолирует ошибки
двух запросов; `awaitClose` освобождает соединение при завершении или отмене.

## Как сравнивать результаты честно

1. Используйте один и тот же вопрос и одну модель, без истории предыдущих ответов.
2. Смотрите на сырой ответ, а не только галочки проверки.
3. Сравните структуру, объём, завершённость мысли и сохранение важной информации.
4. Посмотрите на статус: обрезанный ответ нельзя выдавать за удачно краткий.
5. Сравните входные и выходные токены: дополнительные инструкции тоже увеличивают вход.

Один запуск — иллюстрация, а не статистическое доказательство. Случайность
генерации и нагрузка сервера тоже влияют на результат. В этом задании мы меняем
сразу три инструкции и бюджет, поэтому не можем приписать весь эффект одному
параметру. Для отдельного исследования меняли бы по одному фактору и повторяли
опыт несколько раз с заранее согласованным бюджетом.

Более короткий ответ не обязательно лучше: он может потерять нужный пример.
Хороший результат одновременно соблюдает ограничения и отвечает на вопрос.

## Ошибки, на которые стоит обратить внимание

- **Нет ключа:** настройте окружение и перезапустите IDE, не вставляйте ключ в исходник.
- **Ошибка API:** проверьте модель, поддерживаемые параметры, баланс и сеть.
- **`incomplete`:** посмотрите причину; маленький токен-бюджет не даёт гарантии краткого полного ответа.
- **Обрыв после нескольких слов:** сохраните частичный текст, но не считайте его завершённым.
- **Маркер есть, формат нарушен:** оценивайте условия отдельно.
- **Галочки есть, факты неверны:** проверка структуры не заменяет проверку содержания.

Тесты приложения используют локальный сервер и синтетические ответы. Они
подтверждают обработку протокола, но не доказывают, что реальная модель всегда
выполнит инструкции. Платная проверка OpenAI при реализации второго задания
не выполнялась.

## Короткий рассказ для занятия

«Я отправляю одной модели один и тот же вопрос двумя независимыми запросами.
Слева модель выбирает подачу сама, справа я задаю формат, длину и завершение.
Ответы приходят постепенно и видны рядом. Программа показывает текст без
исправлений и проверяет ограничения. Основной вывод: инструкция задаёт
желаемое поведение, технический лимит ограничивает ресурсы, а проверка позволяет
увидеть, что получилось на самом деле».
