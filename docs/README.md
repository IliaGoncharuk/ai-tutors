## Как определить канонический файл

- Обязательный порядок работы и разрешения — `AGENTS.md`.
- Долговечное описание того, зачем существует проект, — `PROJECT.md`.
- Ограничение с источником и датой проверки — `CONSTRAINTS.md`.
- Текущее положение дел и ближайший план — `STATUS.md`; это снимок, а не
  журнал событий.
- Поведение конкретного челленджа и приёмочные примеры — соответствующий файл
  в `features/`.
- Принятое значимое решение, рассмотренные альтернативы и последствия — новый
  файл в `decisions/`, когда такое решение действительно появится.

Не копируйте полные правила между файлами. Оставляйте краткий указатель и
ссылку на канонический источник. Не создавайте документы без полезного
подтверждённого содержания.
