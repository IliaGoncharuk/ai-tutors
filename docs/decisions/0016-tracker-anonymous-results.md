# 0016. Обезличенные результаты задач Трекера

Статус: принято пользователем 2026-09-27.

## Решение

В заданиях 17–20 вместо названий и ключей задач показываются «Задача 1»,
«Задача 2» и так далее. Ссылки на задачи удаляются, поскольку URL содержит ключ.
Дедлайны, статусы, категории сроков и числовые показатели сохраняются.
День 16 не получает задачи и не требует изменения.

Номер обозначает позицию в текущей выборке, не постоянную идентичность задачи.
При другом фильтре или следующем сборе под тем же номером может быть другая
задача. В утренней сводке номера относятся ко всему снимку, даже если таблица
показывает только строки, требующие внимания.

Обезличивание выполняется на сервере до выдачи данных в MCP и HTTP.
Запрос к Трекеру не запрашивает названия; ключ нужен внутри адаптера для
устранения дублей страниц и сортировки, но исключается из результата.
Поля строки задаются явным списком, поэтому произвольные дополнительные поля
исходного ответа не копируются. Демонстрационный источник подчиняется тем же правилам.
Модель по-прежнему получает только числа.

Новые снимки, результаты запусков, SQLite-сводки и Markdown/JSON-отчёты
сохраняются без названий, ключей и ссылок задач. Старые JSON и SQLite-результаты
обезличиваются при чтении. Предпросмотр старого Markdown строится заново
из обезличенного JSON, а не выдаёт прежний файл.
Уже существующие файлы на диске не переписываются и могут содержать исходные
поля при открытии вне приложения. Их удаление или миграция не входят в изменение.
Для применения серверного кода требуется перезапуск приложения и обновление страницы.

## Варианты и последствия

- Выбран показ обезличенных строк: сохраняется наглядность дедлайнов и работы
  инструментов, но переход к конкретной задаче Трекера больше недоступен.
- Вариант только с агрегатами исключал бы строки полностью и уменьшил бы
  наглядность примеров; пользователь выбрал первый вариант.

## Проверка

Регрессионные тесты используют вымышленные названия и ключи и проверяют их
отсутствие в полном HTTP-ответе, результатах настоящих MCP-вызовов и новых
файлах. Отдельно проверяются чтение прежних JSON и SQLite-сводок без перезаписи,
Markdown-предпросмотр и сохранение исходных числовых показателей.
Итоги каждого дня находятся в его README и `results/verification.md`.
