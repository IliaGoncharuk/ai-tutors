# Решение 0001: локальный веб-интерфейс для первого челленджа

- Статус: принято.
- Дата: 2026-09-02.
- Решение пользователя: «начинать разработку второго варианта».

## Контекст

Первое задание требует минимального вызова LLM через API и вывода ответа в CLI
или простом интерфейсе. VPS не нужен. Для демонстрации важны наглядные
«крутилки», прежде всего температура, при этом публичный репозиторий не должен
раскрывать API-ключ.

## Рассмотренные варианты

1. Node.js CLI — меньше кода и зависимостей, но параметры хуже видны в
   демонстрации.
2. Локальный веб-интерфейс — наглядно разделяет браузер и защищённый серверный
   вызов, но требует больше кода и проверок.
3. CLI и веб одновременно — показывает повторное использование слоя API, но
   избыточен для первого задания.

## Решение

Выбран второй вариант: локальное веб-приложение на Node.js с React/Vinext и
серверным маршрутом OpenAI Responses API. Ключ читается из `OPENAI_API_KEY` и
не отправляется в браузер. Приложение не публикуется и не требует VPS.

Для первого примера доступны модель, инструкция, запрос, температура и предел
выходных токенов. История диалога, streaming, RAG, база данных, авторизация и
инструменты отложены, потому что не нужны для критерия задания.

## Последствия

- Демонстрация параметров понятнее, чем в CLI.
- Появляется локальный сервер и набор frontend-зависимостей, поэтому обязательны
  валидация входа, проверка сборки и аудит зависимостей.
- Решение остаётся локальным: публикация в будущем будет отдельным решением и
  потребует нового разрешения и модели хранения секрета.
- Следующие челленджи можно размещать в отдельных каталогах `challenges/`, не
  превращая первый пример в общий фреймворк преждевременно.
