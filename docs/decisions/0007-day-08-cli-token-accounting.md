# Решение 0007: отдельный CLI Дня 8 с учётом токенов

- Статус: принято.
- Дата: 2026-09-13.
- Решение пользователя: «Давай» в ответ на предложение отдельного CLI
  с подсчётом, тремя сценариями и локальными проверками.

## Контекст и варианты

День 7 уже передаёт всю историю и возвращает usage, но не показывает расход
в интерфейсе и скрывает причины API-ошибок за общим сообщением.

Рассмотрены отдельный CLI Дня 8, расширение Дня 7 и веб-лаборатория. Расширение
потребовало бы меньше нового кода, но смешало бы учебные результаты. Веб-вариант
дал бы графический интерфейс ценой дополнительного сервера и UI.

## Решение

Создать отдельный каталог с собственным циклом `Agent`, тонким CLI и общими
сценариями для API и симуляции. Повторно использовать политики Дня 6 и
JSON-хранилище Дня 7 без изменения их поведения; путь истории Дня 8 отдельный.
До генерации получать серверный подсчёт входа, после — учитывать usage.
Расход текущего запуска хранить отдельно от истории и не сбрасывать при `/reset`.

Обычные запросы проверять локально с резервом ответа. В эксперименте допустить
явный обход этой проверки для наблюдения отказа провайдера. Не включать
автоматическое сокращение истории: оно скрывает исходный эффект переполнения.

## Последствия

- Завершённые задания остаются самостоятельными; новый CLI зависит от двух
  соседних модулей и запускается из полной копии репозитория.
- Серверный подсчёт создаёт дополнительные обращения и задержку перед ответом.
- История и расход имеют разное время жизни. Доступные метрики сохраняются
  в журнале даже тогда, когда ответ не удалось зафиксировать в истории.
- Локальный симулятор проверяет механизм и наглядность, но не доказывает
  токенизацию, качество ответов и ограничения реального аккаунта.
- Большой API-запрос может встретить ограничение размера или TPM раньше
  окна модели. Диагностика сообщает фактическую причину и этап.
