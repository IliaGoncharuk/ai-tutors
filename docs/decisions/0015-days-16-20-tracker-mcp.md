# 0015. Самостоятельные MCP-лаборатории вокруг Яндекс Трекера

Статус: принято пользователем 2026-09-27.

## Контекст и решение

Пять заданий выполняются последовательно, каждое в своей папке с отдельным
локальным сайтом React/TypeScript/Node.js. Исполняемых импортов между днями нет.
Порты 3016–3020. Собственные MCP-серверы используют официальный TypeScript SDK
и локальный транспорт stdio; это позволяет показать реальное подключение без
развёртывания удалённой инфраструктуры.

Общий предмет — только назначенные текущему пользователю задачи Яндекс Трекера.
Внешние операции ограничены чтением. Токен и организация берутся из окружения.
Рабочие данные, расписания и отчёты хранятся вне репозитория.

День 16 показывает соединение и каталог. День 17 добавляет реальный инструмент
Трекера и выбор инструмента агентом. День 18 сохраняет расписание и утренние сводки.
День 19 выполняет фиксированную цепочку MCP-инструментов. День 20 использует
два отдельных MCP-процесса: получение задач и аналитика сроков Трекера.
Такое разделение в Дне 20 учебное: в обычном приложении эти возможности можно
предоставлять одним сервером. GitLab и отдельный файловый MCP-сервер не используются.

Языковая модель получает только рассчитанные показатели и технические результаты
действий. После уточнения пользователя названия, ключи и ссылки исключаются
также из отображаемых и новых сохраняемых результатов; см.
[ADR 0016](0016-tracker-anonymous-results.md). Демонстрационные данные явно отделены от реального API. Разрешённые
реальные проверки всей серии ограничены общим бюджетом $1.

День 18 запускается вручную. Расписание: 09:00 Asia/Yekaterinburg по будням.
Фоновые действия работают при запущенном процессе и бодрствующем компьютере;
закрытие вкладки их не останавливает. При пропуске времени запуска формируется
актуальная сводка после старта, без выдуманных исторических снимков.

## Рассмотренные варианты и последствия

- Пять самостоятельных сайтов выбраны ради независимой демонстрации каждого задания;
  цена — небольшой объём повторяющегося кода.
- Общая исполняемая библиотека уменьшила бы повторение, но связала бы задания.
- Автозапуск Windows и постоянно работающий сервер отклонены: пользователь выбрал
  ручной запуск. Реальное непрерывное 24/7 зависит от доступности процесса и компьютера.
- Передача текстов задач модели позволила бы обсуждать содержание, но пользователь
  выбрал только агрегаты. Поэтому объяснения модели ограничены числовой картиной.

Критерии приёмки каждого дня хранятся в соответствующем файле `docs/features/`.
